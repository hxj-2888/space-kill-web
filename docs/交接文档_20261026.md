两条都实测复现过，根因同类：**「哪些文件属于站点」在三个地方各写一份**。

| P0 | 现象（实测） | 根因 |

> `200 + index.html`。**只 curl 状态码的冒烟测试永远发现不了这类故障。**

## 三、改代码前必须知道的五件事（每条都付过时间）

### 3.1 ★ 门禁会变红，先看它守的是什么，再决定改断言还是改实现

`主区K` 断言守「操作区在流内、面板/输入不得 absolute」，注释写着理由：
**R2 曾把面板贴底，实测压住 1/2/15 号席位，玩家点不到**。

我第一版把 `.ops-dock` 整体改浮层 → 实测四档视口压住 **5~9 个**席位。
**这种情况不能改断言迁就实现。** 最终：`.ops-dock` 保持 `flex:0 0 auto`，
只让面板 `display:none`（高度归零），仅工具条 absolute 到右下角。

反过来，`mobile-layout-check` 的「行动面板必须可见」「场景不得高于视口 60%」
是**面板常驻时代**的规则，与新需求直接冲突 —— 这两条可以改，但要改成**新不变量**
（面板不许无理由常驻），而不是删掉。**删断言 = 把守门的门拆了。**

### 3.2 ★ `clipPath` 不影响 `getBoundingClientRect`

对局内角色帧的内层 `<svg>` 包围盒实测 **334px**，而它的一帧只有 196px
（整张 384×800 行走图溢出帧框，`overflow:hidden` 对 x/y/width/height 溢出无效）。

补了 `clipPath` + `.sk-frame{contain:paint}` **只影响绘制**，包围盒仍是 334px。
要判断"那里是否真的挡东西"，必须用 `elementFromPoint` 命中检测，不能用包围盒相交。

### 3.3 ★ `Uint8Array` 会静默回绕，颜色运算必须钳制

`shade(rgb, 1.22)` 里 R 通道 `255×1.22=311`，写进 `Uint8Array` **回绕成 55** ——
本该是浅红高光的地方变成深青色，在身体上画出一条 3px 竖条。**不报错，只画错颜色。**

定位手段：解码 PNG → 按亮度/色相分类打印 24×40 字符图，一眼看出那一列 `BBB`。

### 3.4 ★ 描边算法要区分「外缘」与「内部空洞」

`outline()` 若对任意透明像素描边，两腿之间的缝会被当外缘涂黑（腰上出现黑块）。
必须从画布四边泛洪标记 `outside[]`，**只描与外缘连通的透明格**。

同理：腿顶必须插进身体 2px（`LEG_TOP=29` vs 身体底 31），否则 1px 缝隙会被描黑，
读作"腰断了一截"。

### 3.5 ★ 断言写在 HTML 里、实现生成在 JS 里 → 断言会误红

`UI1-c` 首版查 `htmlUI1c` 里的 `data-fac=`，但阵营按钮是 `arena.js` 运行时
`innerHTML` 生成的，HTML 里只有空容器。
**结构断言查 HTML，生成物断言查 JS。**
