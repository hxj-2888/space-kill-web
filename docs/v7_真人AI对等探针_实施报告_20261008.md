## 〇、一句话

「AI 和真人除了思维外其他都相同」这条要求，此前**没有任何机制在保证**。
本探针把它拆成三个可判定的维度并实测，结论是：
**动作空间与合法性完全对等，信息边界存在一处真实越界**（沉默状态）。

---

## 一、为什么需要这个探针

仓库里此前有 549 条回归断言，但它们断言的是**功能是否存在**，没有一条断言
「真人与 AI 被同等对待」。缺失的具体后果：

| 缺失 | 后果 |
|---|---|
| 无「AI 能做而真人做不到」的反向断言 | 某个 kind 只给 AI 派发窗口、或 AI 能选真人表单外的值，静默通过 |
| 无「AI 不透视」的边界断言 | AI 读权威真相字段（如 `p.silenceNight`）无人发现 |
| 无「真人被静默歧视」的探测 | 交接文档 §六 记载过两起真人通道静默失效（`inviteAccept`/`chat` 缺 case、`M-speech` 缺 case），都是**玩到才撞见**，不是测出来的 |

第三行是关键教训：**上一批的 `toDecision` default 从静默 `return {}` 改成 `throw`，
正是为了让这类歧视当场炸出来**。本探针是这个思路的延续：从「真人会不会被坑」
和「AI 是不是占了便宜」两端同时加测量。

## 二、三个维度

### 维度① 动作空间对等

**问**：AI 交回的每一个值，真人在表单上点得到吗？

判据直接取自 `form(g,p)` 的 `opts` / `targets` / `num.options` ——
即真人此刻手上那张菜单。AI 返回的值若不在其中 ⇒ AI 多了一份真人没有的动作。

⚠ 这一维第一版写错过两次，都记在这里：
1. 直接比字符串 → 把 `mode:'check'` 与 `opt:'check'` 判成不一致。
   修正：接口词表差异是**已知且正确**的（`toDecision` 是唯一解析口），
   故判据改为「AI 声明的动作类别能否在同 kind 的登记映射里找到」。
2. `num` 按字符串比 → `1.5`（number）与 `'1.5'`（string）误报。
   修正：按**数值**比。

### 维度② 信息边界对等

**问**：AI 决策时读到的字段，真人也拿得到吗？

判据真源是 `js/view.js` 的 `sanitize` —— 仓库里**唯一的视图构建器**
（view.js 顶部 K3 自述「调用点不得绕过」）。探针不自己维护「哪些字段算透视」清单，
而是去问 sanitize 会给同一身份的真人下发什么。

⚠ 这一维踩了三次，都值得留档：

1. **忘了 `view.js` 不在 `profiles.full` 里**（它属 `profiles.ui`）。
   结果：`View.build` 拿不到，判据函数返回「未知 → 视为合法」，
   **整个维度恒判通过**。这是最坏的失败模式 —— 探针看起来在工作，实际什么都没测。
   修正：显式补载 `['view']`，并在开跑前做**判据自证**
   （船员必须看不到异形的 faction/role；自己看自己必须看得到），
   自证不过直接抛错，不许静默降级。
2. **没区分 form 层与 decide 层**。`morph` 表单自己要遍历全场 `role` 才能列出变形池
   （`steps.js:1905` → `morphPool` → `compositionOf`），
   不区分层就会把「引擎在替真人算菜单」报成「AI 透视」。
   修正：读取按 `PHASE` 分档，只判 `decide` 层。
3. **只按 `g.pendings` 取表单**。本探针跑全 AI 局（无真人），`pendings` 恒空
   ⇒ 判据恒返回 null ⇒ 所有读取都落进 VIOLATION ⇒ 「见谁都说透视」。
   修正：按当前步**现算**那张表单（beginStep 做的也只是把它挂到 pendings 上），
   且现算时挂 `PHASE='form'` 以免自我污染。

### 维度③ 合法性与代价对等

**问**：同一 kind 走真人 `toDecision` 解析路径会不会抛错？
答：`toDecision` 未登记的 kind 会 `throw`（v32 的探测器），
所以这一维抓的是「AI 能表达、真人表单表达不了的语义」。

## 三、实测结果（报数区 241–300，60 局，变体口径）

### 维度① 动作空间：**完全对等**

| 项 | 读数 |
|---|---|
| 派发次数 | 15937 |
| 可对照表单 | 15937（100%） |
| AI 交了表单外的 opt | **0** |
| AI 选了表单外的 target | **0** |
| AI 交了表单外的 num | **0** |

⇒ AI 没有拿到任何真人点不出来的动作。**这一维可以放心。**

### 维度③ 合法性：**完全对等**

`toDecision` 解析失败 0 次，31 个 kind 全部登记。

### 维度② 信息边界：**一处真实越界**

| 分档 | 次数 | 含义 |
|---|---|---|
| VIEW | 25167 | sanitize 直接下发 |
| DERIVABLE | 44450 | 统计类，真人可由公开信息推出（见下） |
| OWN_FORM | 1887 | 读者自己表单里已点名 |
| VIEW_PROXY | 781 | 以投影字段下发 |
| DECLARED_SENSE | 2397 | 声明层 `duty.senses` 明确授权 |
| **VIOLATION** | **13841** | **私有真相且不可公开推导** |

`DERIVABLE` 档的论证（**这是本批最需要人审的一处判断**）：
统计类读取（如 `decide.js:661` 无条件遍历全场算「存活医生数」）走的是真相字段，
但其**结论真人也能自己推出** —— 开局公告给构成（`engine.js:846` `openingRosterText`，
实测公告文本确含「生化医师×1、救援医师×1」），
死亡公告给真实阵营与职业（`revealService.js:42` `death: {faction:true, trueRole:true}`），
故「存活医生数」= 公告总数 − 已揭示出局者。
**信息量对等，故不判违例**，但记为 `DERIVABLE` 以便审计，而非藏起来。

`DECLARED_SENSE` 档同样从声明层读答案，不手写：
`SENSE_AUTHORITY` 由 `RD.ROLE_DECL[role].duty.senses` 现场派生
（`infection→infectMarks`、`dying→dyingList`、`poison→poisonList`），
对应速查卡 `sensesQuote` 原文。

#### 唯一的真实越界：`silenceNight`

| 读者角色 | 次数 | 读者角色 | 次数 |
|---|---|---|---|
| alien | 7950 | bodyguard | 177 |
| crew | 1660 | poisoner | 174 |
| inspector | 821 | sheriff | 166 |
| engineer | 539 | xeno | 148 |
| detective | 528 | hunter | 128 |
| bio | 324 | armed | 99 |
| artisan | 315 | assistant | 5 |
| listener | 292 | | |
| convict | 292 | rescue | 223 |

**代码位置**：`js/ai/belief.js:108`（`actF` 活跃度函数）

```js
if (p.silenceNight != null && p.silenceNight >= g.night) n = Math.max(0, n - 2);
```

**为什么是越界**（三条依据，逐条可核）：
1. **速查卡未授权**：`tools/card-audit.cjs`（速查卡 CARD 转录）全文 `silence`
   出现 **0 次**，无任何 `sensesQuote` 声明「谁能看到谁被沉默」。
2. **视图不下发**：`view.js` 的 self 分支下发 `silenceNight`，
   但他人分支只下发 `dying`（救援族）、`infection`（医生族）——
   **不含 `silenceNight`**。即真人玩家看不到别人的沉默状态。
3. **引擎只通知本人**：`steps.js:460` `priv(g, t, '你已被【沉默】…')`，
   `steps.js:461` 是 `god`（仅 DEV 视角）。无任何公开公告。

⇒ AI 用「谁被沉默」下调其活跃度，进而影响 `dangerOf` → 影响投票与击杀选择，
而真人无从得知。这是**信息不对等**，方向对 AI 有利。

**影响面**：`actF` 是 `dangerOf` 的输入之一，故波及全部读 `dangerOf` 的路径
（投票 `decide.js:616`、破坏 `decide.js:921`、发言等）。修它会改变 AI 行为，
**需点头**，本批未动。

> 顺带记一条：`silenceNight` 未进 `duty.senses`，但它在**自己**的视图里下发
> （view.js:71）。也就是说「我能知道自己被沉默」这条是实现了的，
> 「我能知道别人被沉默」这条**没有**实现、也没有声明授权。
> 换句话说：**这是实现层的越界，不是声明层的授权缺口** —— 修法有两条路：
> ① AI 不读（严格按现状声明）；② 补一份公告让真人也能看到（改产品行为）。
> 这是**产品裁定**，不是 bug 判定。

## 七、留给下一批

1. **`silenceNight` 越界的裁定**（本批唯一待决项）：AI 不读，还是给真人加可见性？

4. **B3 决策读材料**：本批证明了「AI 现在读的东西有真有假」，
   修完越界再谈让 AI 更好地用合法证据。
