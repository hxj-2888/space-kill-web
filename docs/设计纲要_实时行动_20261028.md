## 一、一句话

**从"轮到你时系统问你做什么"，改成"你随时走向任何物件、点击、它替你决定能不能生效"。**

## 二、四条设计哲学（本轮拍板，后续改动都要服从）

### 2.1 万物可交互，**指纹**决定是否生效

- 任何玩家都可以点、走、站在任何物件前；**交互永远有反馈**（"这台设备不认你"也算反馈）。
- 是否**实际生效**，取决于 `action-map` 里该动作声明的**权能指纹**与本角色声明的能力是否匹配。
- 指纹的唯一真源是声明层（`js/v66/declaration/roleDecl.js` 的 duty / traits / capability），
  **映射表只引用，不手写角色名**（否则加角色要改两处，违红线 1）。

### 2.2 失败反馈必须与"成功但无事发生"**在外面看起来一样**

这是 2.1 的必然后果，也是最容易做错的地方：
如果"你没有权限"和"你有权限但现在无事发生"的反馈不同，那么**交互本身就变成身份探测器**——
别人看着你点了一下手术台，就知道你是医生。所以：

- 失败文案统一为中性（"设备没有响应 / 现在用不了"），不写"你没有权限"这种带身份的措辞；
- 动作的**可见表现**只依赖"这个人站在这里做了一个动作"，不依赖成败（见 §4.3）；
- 门禁要有一条："任何失败分支的文案不得包含角色名/阵营词"。

### 2.3 移动可以骗人，但只能是**有意的骗**

AI 的可见移动可以与其真实行动矛盾（诱饵路线），但必须满足"同一时刻只在一个地方"、
且诱饵路线有身份合理性（好人装做任务、异形装路过）。禁止"随机乱走"式的矛盾。

### 2.4 视野 = 半径 ∩ 不跨墙

不是全船可见，也不是"只看同房间"。详见 §4。

## 三、时间模型：步骤表降级为**相位时钟**

| 项 | 旧（步骤机） | 新（实时） |
|---|---|---|
| 夜间 | 按 `0.1/1/2/3…` 串行派发，等人决策 | **一段固定时长**（建议 90s，待定）+ 结算 tick 0.5s |
| 白天讨论 | 讨论步骤 + 发言窗口 | **60s**（本轮拍板） |
| 会议投票 | 步骤 `M-vote` | 保留一次性流程（不能实时投票） |
| 权能解锁 | 到某步才解锁（异形等侦探查完才能出刀） | **取消**：开局即有，改由**冷却 / 弹药 / 额度**约束 |
| 决策窗口 | 每人每步一个 | 仅**一次性长文本**保留窗口（留言 / 投票 / 私聊正文），超时即过 |
| `g.step` | 派发依据 | 退化为**日志标签 / 夜数推进** |
| 胜负判定 | 步骤末 | **每个动作结算后都判**（实时化后判负变得频繁） |
| 自动机制（感染致死、破坏进度、冷却恢复） | 步骤触发 | **tick 触发（0.25s）** |

窗口超时自动进入下一步这条**已存在**（`main.js` 的 `deadline` + 弃权分支），改造时复用，不重写。

### 3.2 移动与输入（本轮定：点地面寻路）

| 项 | 规则 |
|---|---|
| 移动 | **鼠标 / 触屏点地面 → 自动最短路径**（复用 `ship-map.walkPath` 的 A* 与视线拉直） |
| 改向 | **连点即改向**：每次点击重算路径，不必等走到（"频繁点击就等于自己在控制方向"） |
| 代价 | 承认失去 WASD 的连续微操 —— 换来"边走边打字 / 边走边点物件"（§6 气泡的前提） |
| 键盘 | 降为可选辅助；输入框聚焦时不抢键 |
| 为何要这样取舍 | 因为"行走中实时打字"与 WASD 在键盘上直接冲突（W 既是走路也是字母）。点地面把移动与输入彻底解耦 |

## 四、视野与遮挡

1. **半径**：以自身为中心的圆，**9 格**（VISION_R，见 js/scene/const.js；它同时是枪的射程）。
   **已实装（R1）**：SKScene.inSight(from,to) = 距离 ≤ 9 ∩ SKShip.losClear；
   渲染层据此裁剪，**看不见的人不进 DOM**（不是 display:none，防 F12 读坐标）。
2. **不跨墙**：视线被房间墙壁/走廊侧壁挡住（本轮拍板：「枪击和目击不可以跨墙」）。
   技术后果：需要"点到线段距离 + 线段与墙矩形求交"的几何能力 ——
   这与地图改造（斜廊）共用同一套基元，建议**同批实现**。
3. **软边**：半径外压暗而不是硬删，避免"人凭空消失"（与"消除玩家消失系统"一致）。
4. **目击只记事实**：`{tick, 观察者, 被观察者, 房间, 是否看清动作}`。
   本轮拍板：「谁举刀挥枪不一定看得见」——**动作是否可见取决于遮挡与距离**，
   看不清时只记"某人在某房间"，不记"他在做什么"。
5. 小地图仍只显示自己（否则等于全图透视）。

**尸体（本轮定）**：死在哪儿就留在哪儿，**只留一个晚上**；可见性同上面四条口径；
`doctor.revive` 只在尸体存留期间可发起；白天清除（暂定）；本轮不做拖尸/藏尸。

## 五、动作生效学（6 道校验，缺一即崩）

每个动作请求 `{ playerId, actionId, target, tick }` 必须依次过：

1. **指纹**：该动作的权能 ∈ 该玩家角色的能力集（声明层派生）；
2. **场所**：人在该动作允许的房间/物件旁（映射表 `场所` 列）；
3. **距离**：近身 ≤1.2 格 / 同房间 / 远程 ≤12 格（映射表 `距离` 列）；
4. **视线**：远程动作与目击都必须无墙遮挡；
5. **资源**：冷却结束、弹药/额度足够（映射表 `冷却` `消耗` 列）；
6. **目标**：存活、未被保护、不是自己（按动作定义）。

任一条不满足 → **中性失败反馈**（§2.2），不消耗资源。

**不可抢原则**（本轮拍板）：军械库的武器箱与弹药**不能被其他玩家取走/抢夺**。
"抢"在实时场景里表现为"别人先点了"——这条要落成：武器箱的产出只进**指纹匹配者**的背包，
且**产出期间不可被中断进别人手里**（可被打断进度，但已完成的那份归属唯一）。

## 六、争夺模型（同一处、同一时刻）

**一个"维修进度"取代所有倒计时**（0~24，修满 ⇒ 人类胜利）—— 它是原文"倒计时 24 昼夜"的镜像（进度 = 24 − 倒计时）：

| 推进方式 | 变化（**原文数值**） | 说明 |
|---|---|---|
| 每过一个晚上 | **+1** | = 原文"倒计时自然流逝 −1" |
| 工程师维修 5s | **+1.0 ~ 1.5**（6 档自选） | 追加维修同额，个人全局 3 次 |
| 船员 / 侦探协助维修 | **+0.20 ~ 0.50**（7 档） | 原文 4a 的 assistRepair |
| 净破坏量跨 3.0 / 6.0 | **−2.5 / −5.0** | 原文"停摆"档，每档一次、不可逆 |
| 净破坏量跨 9.0 | 人类进度胜利**永久失效** | 只能靠清场取胜 |
| 破坏（异形/外星人） | 净破坏量 **+1.5~2.0 / +2.0~3.0** | 外星人破坏全局 1 次，附**停转夜** |

**控制台锁**：同一台机器同一时刻只允许一人有效交互（先产生"实际指纹交互"者占用 5 秒，他人被禁用）；
**只有指纹匹配者才会占用** —— 不会修的人来点不会占住机器，否则就是恶意占位。
占用与完成本身就是目击信息（谁站在控制台前），这是实时版推理的主要来源之一。

## 七、阵营不对称（本版的核心张力）

| 维度 | 人类（武装） | 异形 / 外星人 |
|---|---|---|
| 击杀方式 | **枪击**：**射程 = 视野**（半径 ∩ 不跨墙），开局自带枪弹 | **近身 ≤1.2 格（拽回 + 硬控）** |
| 动作时长 | **1s**（= 4 tick @0.25s） | **0.5s**（= 2 tick，所有近身击杀统一） |
| 可打断性 | 可以被打断（受击即中断、弹药不退还） | **不可打断**：拽住目标后这 0.5 秒无人能救 |
| 命中判定 | **锁定 + 实体子弹**：开枪锁定视野内目标；子弹以 **30 格/秒**飞行，目标脱离视野则沿切线直飞、**可误伤（友军也算）** | 贴身即命中（硬控），无躲避 |
| 暴露 | **枪声**：大范围（暂定 20 格）都知道"有人开枪"+方向 | **无声**，只有视野内的人看见动作 |
| 资源 | **开局自带枪 + 弹药**；后续只能去军械库补弹（5s，需指纹） | 刀数 / 感染额度（按夜 / 按局） |
| 冷却 | 8s（数值待调） | 个人夜技槽：**一夜一次**（出刀/感染/破坏/结茧共享） |
| 反制 | 掩体、安全室、对射（把凶手打成濒死） | 护盾 / 保镖（击杀前判定）；**"打断"已取消** |

**近身击杀的完整规则**：
1. 贴身命中后**把目标拽回**并**硬控**，全过程 **0.5 秒**、**不可打断**（没有"打到一半被救下"）；
2. 这 0.5 秒内凶手若吃到枪击：**击杀仍然完成**，完成后凶手转**濒死 —— 可救**（不是必死）；
3. 也就是说人类的反杀不是"救下这一刀"，而是"拿一枪换对方倒地"。

> 设计意图：人类 = **远程但必须看见、且一枪暴露自己**；异形 = **安静、贴到必杀，但 0.5 秒里会被人换掉**。
> 参数可调，方向不能翻。

## 八、确定性纪律（红线 3 的延续）

实时点击会让"点击顺序"污染随机流，因此：

- 所有随机值只在 **tick 结算**时抽取；
- 同一 tick 内的动作按固定键排序：`房间序号 → 玩家编号 → actionId`；
- 动作请求先入队，tick 统一结算；"按下到生效"最多延迟 1 个 tick（0.5s）。
- 复盘/蒙特卡洛读的是 tick 序列，不是点击序列。

## 十、非目标（本轮明确不做）

- **联机**：不做，只留痕（现有 `net.js` 是回合提交式，实时化等于重写；将来必须是服务端权威 tick）。
- 不在本版做"多层船体/楼梯"。
- 不做全船可见；不做"任务点"式小交互物（交互仍只落在房间里的物件上）。
- 不做回声定位/声音可视化（枪声只给"有人开枪+方向"这类文字/图标信息）。

## 十一、待定（下一轮讨论项）

已定：夜晚 **90s**、白天讨论 **60s**、技能类 **5s**、**近身击杀 0.5s**、**枪击 1s**、**tick 0.25s**、移动=点地面寻路、
尸体留一夜、共享冷却=**个人技能槽**、破坏/维修=控制台锁 + 倒计时增减（**±24s**）、
濒死**可救**、枪击**必须目标在视野内**且**走位可躲**、警长/猎手**开局自带枪弹**（补弹 5s）。

仍未定：

1. ~~tick 频率~~ 已定 **0.25s**（0.5s 出刀 = 2 tick）；
2. 视野半径（建议 9 格）与软边强度；
3. 枪声范围（建议 20 格）与"方向"的表达方式；
4. 近身距离（建议 1.2 格）是否改为"同房间即可"；
5. 武器箱 / 弹药 / 药剂的产出额度（时长已统一 5s）；
6. **破坏倒计时**：初始值、破坏 +N、维修 −M、触发后果的阈值；
7. **硬控期间细则**：被拽住的人这 2 秒能否打字；拽回落点（贴身 0.6 格？）；
8. **护盾 / 保镖的判定点**：击杀开始瞬间，还是 2 秒结束命中时；
9. 会议触发条件（随时按通讯台？需要冷却？破坏期间能否开会？）。
10. **破坏倒计时阈值**：±24s 已定，"累到多少触发后果"未定（建议 72s）；
11. **初始弹药数与补弹量**：自带几发 / 补弹给几发；
12. **濒死救援细则**：谁能救（医生？任何人？）、几秒、是否耗药剂、濒死者能否打字；
13. **0.5 秒反杀窗口**：是否给"刀后 1 秒内被击中仍转濒死"的宽限（否则人类几乎无法反制）。
