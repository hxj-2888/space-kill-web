## 一、列定义

| 列 | 含义 | 取值 |
|---|---|---|
| `id` | 动作稳定标识 | `alien.knife` / `crew.shoot` … |
| `kind` | 兼容旧引擎的 kind（过渡期用，最终退役） | 引擎 38 个 kind 之一 |
| `权能` | **指纹**：`roleDecl` 中该角色声明的能力键（⟂ 待核准） | 人类/异形/外星人/职务 |
| `场所` | 允许发起的房间 + 物件（引用 `space.js` 的 `k`）；`任意` = 不绑物件 | `medical/surgery` |
| `目标` | 目标类型 | `—` / `self` / `other` / `corpse` / `prop` / `area` |
| `距` | 距离门槛 | `触`=≤1.2 格 · `房`=同房间 · `远`=≤12 格 + 视线 · `—` |
| `时长` | 完成时间（秒）；被占期间不能做别的 | 数值 |
| `冷却` | 数值秒 / **`夜×1(Gn)`=与同组共享"一夜一次"** / `0`=无 | 见 §三 |
| `消耗` | 弹药 / 刀数 / 感染额度 / 药剂 | 短串 |
| `结算` | 结算方式 | `即`即时 · `进`进度条（tick 积分）· `实时`连续（聊天）· `窗`一次性窗口（投票/留言） |
| `反制` | 被打断/被抵消/被保护的方式 | 短串 |
| `目击` | 谁能看到什么 | `动`=视野内且无墙遮挡可见"在做什么" · `无` · `声`=广播 · `泡`=气泡（§六） |
| `争夺域` | 同一资源上的对抗域（见 §四） | 域 id / `—` |
| `AI` | AI 主动使用的倾向（供 `ai/decide` 规划） | 高/中/低/— |

> 「所有玩家都能点」是**前提**：表里的 `权能` 只决定"点了到底生不生效"，不决定"能不能点"（纲要 §2.1）。

## 一之二、权能指纹的真源（查过代码，不是猜的）

"指纹"不是新造的东西，它已经存在于声明层，分三个来源：

| 来源 | 位置 | 键 | 适用范围 |
|---|---|---|---|
| **grants**（角色授予的能力键） | `js/v66/declaration/roleDecl.js` 每个角色的 `grants: [...]` | 共 **16 个**：`brew` / `craft` / `extraRepair` / `morph` / `poison` / `protect` / `repair` / `revive` / `safeRoom` / `save` / `shoot` / `sniff` / `transfer` / `treat` / `vaccine` / `wiretap` | 人类职业的能力（维修、开枪、治疗…） |
| **机制位**（异形/外星人的分支） | `js/engine/steps.js` 的 4b/5/7 等步骤 + `roleDecl` 的 `dir` / `charges` | `alien.kill` / `alien.infect` / `alien.destroy` / `alien.weave` / `xeno.destroy` / `xeno.check` / `xeno.evolve` / `xeno.cure` / `xeno.silence` | 非人类阵营的主动技能（多数不在 grants 里） |
| **基础能力** | 所有人共有（无 grants） | `base.talk` / `base.chat` / `base.vote` / `base.meeting` / `base.will` / `base.speech` | 社交与会议 |

**映射规则（接线时逐行落定）**：
1. 行里的 `权能` 一律写成上面三种键之一，**不再写中文名**；
2. 若该能力在 `roleDecl.grants` 里 ⇒ 键必须**逐字等于** grants 里的字符串（门禁直接比对）；
3. 若属"机制位"或"基础能力" ⇒ 必须在 `action-map.js` 的 `CAPS` 表里显式登记（含来源注释），门禁比对这张表；
4. **反向**：`grants` 里出现、但本表没有任何动作的键 ⇒ 判红（防"声明了但点不出来"）。

> 注意：`grants` 只有 16 键，而本表有 44 行动作 —— 差额正是"机制位 + 基础能力"，
> 这也是为什么不能用一个简单的白名单校验，而要按来源分三类。

> `kind = —` 表示"引擎尚未实装该动作"（`save` / `poison`：前者是本轮新增的濒死救援，
> 后者属 A6 pending 的毒师）。这类行允许先登记在表里，但门禁 AC1 会把它们单独列出来，不允许悄悄增多。
>

## 三、冷却组（**个人技能槽**，一夜一次）

> **语义（本轮已定）**：共享冷却 = **单个玩家自己的技能槽**。一个人用掉任一"夜技"，
> 只让**他自己**其余夜技本夜不可用；**不影响其他个体**（别人照样能修、能查、能杀）。
> 所以下表是"每人各持一份"的组，不是全局开关。

| 组（每人各持） | 成员 | 规则 | 状态 |
|---|---|---|---|
| **G1 异形夜技** | `alien.knife` / `alien.infect` / `alien.destroy` / `alien.weave` | 本人一夜只能用其一；用掉后**本人**其余三个本夜不可用；次日恢复 | ✅ 已定 |
| **G2 外星人夜技** | `xeno.kill` / `xeno.check` / `xeno.silence` / `xeno.evolve` / `xeno.cure` | 同上（本人一夜一次） | 《待裁·成员范围》 |
| **G3 人类夜技** | `detective.check` / `crew.info` / `crew.patrol` / `crew.sniff` / `crew.wiretap` / `doctor.surgery` / `doctor.revive` / `doctor.suppress` / `crew.guard` / `crew.safeRoom` / `alien.ferry` | 同上（本人一夜一次） | 《待裁·成员范围》 |

**不进入共享组（劳务型，冷却 0）**：`crew.repair` / `crew.crewRepair` / `crew.crewAction` / `doctor.clean` / `doctor.medicine` / `crew.craftAmmo` / `crew.takeGun`。
这些是**劳务**不是**技能**：只要机器没被别人占着，谁都能做，且没有"一夜一次"限制。
（否则破坏生效后没人能做第二次维修 —— 破坏会变成必死局。）

## 四、维修进度与破坏（**数值全部沿用规则原文**）

**原文口径**（`js/state.js` 的 `countdown: 24`、`net10`，`js/engine/steps.js` 的步骤 4a/4b/11）：

```
倒计时 = 24 昼夜（初始）；每夜步骤 11 自然流逝 −1；≤ 0 且人类未全灭、未触发 9.0 ⇒ 人类胜利
净破坏量 = 异形+外星人破坏累计 − 维修削减；最低 0，不预存信用
  异形（未进化）破坏      +1.5 ~ 2.0（步长 0.1，自选）
  异形（破坏进化）破坏    +2.0 ~ 3.0
  外星人破坏（全局 1 次） +2.0 ~ 3.0，并触发「停转夜」：次夜维修全部无效、倒计时不流逝
  维修（工程师/助理）     −1.0 ~ 1.5（步长 0.1，6 档）；追加维修同额，个人全局 3 次
  协助维修（侦探）        −0.20 ~ 0.50（步长 0.05，7 档）
  削减只作用于**已累计**的净破坏量（不能削当夜破坏）
停摆（净破坏量跨档，每档一次、不可逆）：
  跨 3.0 ⇒ 倒计时 +2.5      （= 维修进度 −2.5）
  跨 6.0 ⇒ 倒计时 +5.0      （= 维修进度 −5.0）
  跨 9.0 ⇒ 人类倒计时胜利**永久失效**（只能靠清场取胜）
维修暴露：累计维修 4.0（工程师）/ 3.0（助理工程师）⇒ 暴露
```

**本表的表述**（等价换算，便于实时界面显示"还差多少"）：

| 事件 | 维修进度 |
|---|---|
| 每夜过去 | **+1** |
| 工程师维修 5s 完成 | **+1.0 ~ 1.5**（自选档位） |
| 船员 / 侦探协助维修 5s | **+0.20 ~ 0.50** |
| 净破坏量跨 3.0 / 6.0 | **−2.5 / −5.0** |
| 净破坏量跨 9.0 | 人类进度胜利**永久失效** |
| 进度达 **24** | **人类胜利** |

**控制台锁**：同一台机器同一时刻只允许一人有效交互（先产生"实际指纹交互"者占用 5 秒，他人被禁用）；
**只有指纹匹配者才会占用**（不会修的人来点不占机器）。占用与完成本身就是目击信息。

其余争夺域不变（`craft#N` / `terminal#N` / `box#1`）。
