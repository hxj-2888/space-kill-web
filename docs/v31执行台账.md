1. **词表统一**：`Tiers.PROMISE = { tiers, STRONG/MID/WEAK, cred(0.05/0.15/0.30), miss(8/20/35), name(C/B/A-), settle(vote/announce/none) }`。

# 批 3：战术库 37 条接线 + 三项裁定（v31 批 3）

依据：方案 §8.1 批 3（「战术库 37 条接线，方案称为平衡的真实杠杆」）+ 用户对三项待裁定的拍板。

## 一、问题：37 条战术资产是死数据

`js/corpus/tactics.js` 的 `ALIEN`（N349~N372，24 条）与 `XENO`（N373~N386，14 条）此前是**纯字符串数组**：

```js
const ALIEN = { zero: ['N349 主动附和', ...], low: [...], mid: [...], high: [...] };   // 全仓零引用点
```

- `Tactics.ALIEN` / `Tactics.XENO` 在整个 `js/` 里**没有任何消费者**（唯一被消费的是 `SAFE`、`filterClaims`、`phaseOf`）。
- 后果：异形/外星人的**全部专属手段一件没接**——不会冒领、不会卖队友、不会欺诈感染、不会分工。
  这不是「战术弱」，而是「工具箱是空文件」，是台账 D1（AUC 敌友倒置）与 D2（AI 同质化）的直接根因。
- 原有的 `PHASES`（N387~N396）虽已由 `phaseOf` 消费，但只输出标签（`alien: 'zero-only'`），标签本身也没人读 → 调度层同样是空转。

## 二、改造：字符串注释 → 结构化选项池

```js
const A = (id, label, risk, extra) => Object.assign({ id, label, risk, act: null }, extra);
const ALIEN_OPTS = [
  A('N357', '冒领船员', 'mid', {
    when: (g, p) => !p.claimedRole && detectiveAnnounceRecent(g) === 0,
    act: { kind: 'claimRole', payload: { role: 'crew' } },
    note: '限神探公告沉默期（定案 20）' }),
  ...
];
```

字段语义：

| 字段 | 含义 |
|---|---|
| `risk` | zero / low / mid / high（沿用原分档） |
| `when(g,p,ctx)` | 该战术在当前局势是否可用（**只读公开信息或己方自有信息**，不读真相） |
| `say` | 出口发言文本池（语言层语料规格，不产 Claim） |
| `act` | 需要落成 Claim 的行为 `{kind, payload}`，经 IR.mk 出口后再过 `filterClaims` |
| `note` | 原条目注释（保留可追溯性） |

**认知类条目**（N361 清洗两难 / N366 轮换破坏 / N367 破坏选小值 / N369 信息优势无法变现 / N370 沉默的战术价值 / N371 冒领窗口 / N385 第三方不能赢太多…）没有出口动作——它们的语义本来就是「什么时候别做什么」，`act = null` 并保留 `note`，由 `PHASES` / `decide` 的调度逻辑承担。这部分不是「没接」，而是「接在门禁上」。

## 三、唯一消费者入口

```js
Tactics.pickTactic(g, p, rng, ctx) → { opt, text, claim } | null
```

- 分层加权抽取：zero 3 / low 2 / mid 2 / high 1，一次最多出 1 条（避免一开口就是战术广播）。
- `ctx` 由 `decide.speak()` 注入，全部是「该 AI 自己算得出来的量」：`accusedBy()` / `susp(id)` / `topSuspect()`。
- `decide.speak()` 非人类分支消费；产出的 Claim 再经 `Tactics.filterClaims`（Z 档：N397 禁区 / N398 指纹 / N399 蛰伏暴露 / N400 冒领窗口，**生成前拦截**）。

## 四、方法论修正：门禁不能读「己方怀疑度」

首版把 N358 卖队友的门禁写成 `susp(队友) ≥ 35`，实测 500 局 **0 次**。探针（60 局 / 21136 次异形发言）定位：

| 统计项 | 次数 |
|---|---|
| 异形发言总次数 | 21136 |
| 其中 night ≥ 4 | 8790 |
| 其中队内有存活队友 | 19137 |
| 其中队友怀疑度 ≥ 35 | **0** |
| 其中队友怀疑度 ≥ 20 | **0** |

根因：**异形对自己队友的怀疑恒为 0** —— 认知层的 `E` 先验把同族标为 `alienMate`，`hostile` 只对其他阵营计数。用「己方怀疑度」当卖队友的门禁，在结构上永远不可达。

改为读**公开可见的队友处境**：`被指控 ≥ 2 次` / `已公开暴露（repairExposed）` / `已被揭示（revealed）`。修后 N358 27 次 / N359 47 次。

## 三、N414~N417：保护优先级从「硬规则」改为「效用权重」

落点三处（`js/ai/decide.js`），权重真源 `Tiers.PROTECT`（唯一真源，可标定）：

| 编号 | 角色 | 旧实现 | 新实现 |
|---|---|---|---|
| **N414** | 保镖 `guard` | `if (exposed.length) return exposed[0].id` —— **硬规则**（等于「必须优先保护 ④ 暴露者」） | `U = −dangerOf + protectionBonus(...,'guard')`，经 `argmaxProtect` 选择 |
| **N415** | 警长 `patrol` | `[自己, 已暴露工程师, dangerOf 最低 1 人]` —— 同上为硬插队，且忽略「不可替换性」（技能岗与船员同权） | `U = −dangerOf + protectionBonus(...,'patrol')` 取前 3 |
| **N416** | 医生 `doctor` | 治疗候选仅「感染者」 | 候选扩为 `感染者 ∪ 关键预告者`（**预投抗体**：「治疗即赋予抗体」，`steps.js '8'` 的 `had=false` 分支照样授予 —— 这才是「抵 1 次感染」的真实语义） |
| **N417** | 下界硬约束 | — | `argmaxProtect`：`ε ≥ Tiers.PROTECT.floor(0.05)`，且**硬源确证（conf=1）时也不归零** |

**为什么 N417 必须有独立的入口**：通用 `argmax` 在 `conf=1`（分布退化为单点，来自 `knownLockOf` 硬锁）时
`ε=0`。保护决策问的是「要不要保他」，与「他是不是敌人」的置信度无关 ——
若沿用通用入口，硬锁为人类的关键职位（④ 暴露的工程师、③ 公告过的金水）会被机械地夜夜保护，
保护优先级就退化成硬规则，直接违反噪声章 20.1「效用必须连续算出来」与「不制造最优」。
回归断言用 400 次抽样锁死「conf=1 下次要选项选择率 ≥5%」且「通用 argmax 仍归零」。

**保护优先级阶梯（`Tactics.protectPriority`，只读公开事实）**：
`3` 已预告（可验证强承诺者）／④ 暴露的关键职位 ＞ `2` 已被官方确证为人类的关键职位 ＞ `1` 高价值未确证 ＞ `0` 其余。
自保另有固定权重 `Tiers.PROTECT.self`（文档 5.1 明列「自保」是 AI 可以不合规地不保护预告者的理由之一）。

**归属（文档 5.4）**：N414~N417 与浑水摸鱼 v21 同制 —— 改变**行动效用**，不是**证据**，
因此**不进 `channels.data`**（塞进总表当通道 = 给保护目标选择加一个硬阈值）。回归断言锁死 `N414/N417` 不在总表。
