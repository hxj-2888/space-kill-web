## 二、实施：新增 `duty` 字段（AI 职责面）

按项目「声明层为唯一真源」的纪律，不另建平行结构——**在声明层加一个字段 `duty`**，三张词表 + `audit()` 强制取值合法：

```js
duty: {
  mutex:  ['treat','selfSave','brew'],       // 当夜互斥（速查卡「X 选一」）
  senses: ['infectMarks','antibodyFeedback'],// 专属主动情报面
  cost:   null,                               // 明文代价键
}
```

与既有 `visibility` 分列的理由：`visibility` 是**规则授予的被动可见**（公告批次／私反馈族），`senses` 是**该角色专属的主动情报面**。两者不能混。

新增访问器：`mutexOf / sensesOf / costOf / hasSense / mutexBlocked`。
新增词表：`DUTY_ACTION`（33 个动作身份）、`DUTY_SENSE`（24 项情报面）、`DUTY_COST`（8 项代价）。
新增台账：`IMPL_GAP`（卡载与实现的差异，见第三节）。

### 审计加了两道真牙

1. `duty` 子键与三张词表的取值合法性；
2. **`mutex ⊆ charges ∪ grants ∪ 进程注册表 owner ∪ IMPL_GAP` 的交叉核对** —— 这条当场抓出我自己数据里的 3 处矛盾（`artisan.cast/castFast` 归 `SKProcess` 所有、`xeno.selfHeal` 属未实装），修正后才归零。

`roleDecl.audit()` 违规数 = **0**。

## 四、实施：修掉一个真缺陷 —— 异形在步骤 7 选「结茧」

这是速查卡直接抓出来的**规则误读**：

- 卡（异形条）：「每夜出刀／感染／破坏／结茧四选一（**破坏／结茧在步骤 4b，出刀／感染在步骤 7**）」
- 引擎步 `'7'` 的表单只有 `kill / infect / none`（`steps.js:1146-1151`，寂灭期 desc 写明「菜单收敛为出刀/感染」）
- 但 `decide.js` 把 `cocoon` 放进了**步 7** 的选项池并返回 `{act:'cocoon'}`

**后果两处，均已实测：**
1. 引擎步 7 的提交处理只有 `kill`（`steps.js:1163`）/`infect`（`:1172`）两个分支，`cocoon` 落入 else 被**当作「放弃行动」**——异形的结茧意图被静默丢弃；
2. `steps.js:1189` 的 `p.guardStreak = (act==='kill'||act==='infect') ? 0 : +1` 因而被连带 +1 ⇒ 一个「连续未被抵挡」的无关状态被非法选项污染。

实测 **169 次 / 150 局**。修复：步 7 选项池回归 `[kill, infect, none]`；寂灭分支同样对齐（原来还把 `infect` 挤掉了）；删除已无来源的 `{act:'cocoon'}` 返回分支。

**明确不做的事（留给下一批）：** v4 6.2「反拖延」机制（`guardStreak` 疲劳）原本挂在步 7 的 `uCocoon` 上 —— v26 那次「修复」是建立在「结茧属步 7」这一误读之上的。修掉误读后该机制在步 7 无处附着；按卡它的正确归属是 4b 的结茧闸门。但改它会直接改变破坏/结茧的发生频率，属**策略权重**，必须单独一批 + 同种子 A/B。这条已写进 `decide.js` 的注释，不留悬案。
