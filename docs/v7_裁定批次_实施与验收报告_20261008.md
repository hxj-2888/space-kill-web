## 二、裁定① 自我治疗额度

### 卡上的空白

速查卡的外星人额度行只写了夜晚免疫 / 破坏 / 双刀 / 乔装，**未列自我治疗**。
上一批据此按「疑为每夜回复」实现（无条件赋 1），并把该推断登记进 `IMPL_GAP` 等正文确认。

### 现在的口径（裁定）

**每夜有感染标记自动赋予一次额度。**

行为变化（须知）：无感染标记的外星人当夜不再得到额度，其自我治疗窗口从「每夜可选」
收窄为「有感染标记的夜晚可选」。这是裁定的直接后果，不是副作用。

为什么这个口径更自洽：自我治疗的效果是「清除自身感染并赋予抗体」。没有感染标记时该动作
无对象，而额度到账、动作可用、结果却是「没东西可清」——原口径会周期性产出无效行动位。
按感染标记发放后，额度到账 ⟺ 该动作当夜有意义。

额度是否跨夜累积：**卡与裁定均未规定**，故保持「只在有标记时赋值、不清零」的既有语义 ——
未用掉的额度保留到下一夜。若日后裁定要求累积或到期作废，改 `engine.js` 一行即可。

### 验证（`tools/verify-cureself.cjs`，确定性）

```
①a 无感染标记 → cureSelf = 0        [通过]
①b 有感染标记 → cureSelf = 1        [通过]
①c 下一夜无标记 → cureSelf = 1      [通过]  未用额度不被清零
②  步骤 8 req 派发 kind=xenoCure    [通过]
③  结算：感染已清除 + 写入抗体       [通过] ×2
④  抗体拦截：A 授予夜+1 拦截 / B 授予夜+2 落地   [通过] ×2
汇总：通过 8 条，失败 0 条
```

顺带修掉一处**既有**测试构造缺陷：`④B` 此前恒失败，因为该段只改 `g.night` 就调
`applyInfection`，却没清当夜的其他防护层标志 —— 真实第 1 夜警长巡逻留下的 `patrolInf=true`
仍挂着，在「授予夜+2」那例里被巡逻层拦下。对 HEAD 版脚本跑同一引擎同样失败，**不是本批回归**。
现改为清空除抗体外的全部防护层，使 `antibodyNight` 成为唯一变量。

## 三、裁定② 协助维修拆成独立窗口

### 卡载

> 夜间行动：步骤 2 查验 ｜ 步骤 4a 协助维修（二者当夜二选一，亦可依 2.4 放弃行动）
> 7 档自选值 a ∈ [0.20, 0.50] 步长 0.05

改动前：协助维修**折在步骤 2 的同一张菜单里**（`'repair'+a` 前缀 opt），二选一靠
「同一张菜单」隐式成立，落位差异登记为 `informational`。

### 改法，以及为什么这样改

| 层 | 改动 |
|---|---|
| 声明层 | `crew.actionSteps` 加 `'4a'`（主行动位仍是 `'2'`；步骤 2 的派发本来就按 role 键直接判，不走 `canActAt`，故不受影响） |
| 步骤 4a 的 `req` | 改用 `ACT.actionSlots(...)` 而非 `canActAt(...)` |
| 步骤 4a 的 `form` | 新增船员分支，`kind='crewRepair'`，7 档 `assist+value` + 放弃 |
| 步骤 4a 的 `run` | 协助维修值改由**本步**决策提供（保留旧路径兼容）；停转夜提前 return 处作废预留值 |
| 步骤 2 的 `form` | 移除 7 档协助维修，只留查验与放弃行动 |
| 步骤 2 的 `run` | 真查验者写 `p.branch='check'` |
| `toDecision` | 登记 `case 'crewRepair'` |
| `decide.js` | 新增 `case 'crewRepair'` |

**`canActAt` → `actionSlots` 是必需的**：`canActAt` 只认**主**行动位
（`derivation/actions.js` 的 `rolesAt` 按 `actionStep === step` 过滤），次要行动位对它无效。
不改则声明的 `'4a'` 只落在纸面、派发认不到 —— 那正是「造幽灵步位」。今日除船员外无任何角色
把 4a 列为次要位，故该改动当前行为保持。

**互斥用既有的 `p.branch` 机制**：步骤 2 真查验 → `branch='check'` → 4a 的 `!p.branch` 把他过滤掉。
`p.branch` 每夜由 `engine.js` 的重置清零，不跨夜残留。人类角色本无 branch 赋值路径
（赋值只在 0.1/4b/5/8 四处，均为异形行动），故加 `!p.branch` 不影响工程师等其他 4a 参与者。

### 关键取舍：三路效用比较**留在步骤 2**

`decide.js` 的 `crewAction` 仍算 `uCheck` / `uRepair` / 不做三个候选并取 argmax：

- 胜者是查验 → 真查（写 branch，被 4a 排除）；
- 胜者是协助维修 → 步骤 2 只**预留**档值，由 4a 的 `crewRepair` 执行；
- 胜者是不做 → 4a 不出手。

`crewRepair` 只做「执行预留」：`p.repairValue == null` 就返回 `mode:'none'`。

**不做「两步各自重新决策」那种更彻底的拆法**：那样 `uCheck` 与 `uRepair` 不再相互比较，
而是各自与 0 比较 —— 只要 `uCheck>0` 就去查验，`uRepair` 更大的那些夜晚反而放弃维修。
那是**策略权重的系统性偏移**，超出「拆窗口」的授权，故未做。
A/B 结果印证了这个判断：**指控条目 +0.2%**，行动组合确实没被挪动。

### 验收（`tools/probe-crew-window-mutex.cjs`，确定性 + 80 局）

① 7 档数值 = [0.2,0.25,0.3,0.35,0.4,0.45,0.5]          [通过] 与卡载逐档相符
② 同夜既查验又协助维修 = 0 次（4a 派发 477 次）          [通过]

## 七、本批自身修掉的真实缺陷（留着当记录）

2. **`SKRoleDecl` 未导出 `chargeOf` 访问器** —— 我在 4a 写了 `RD.chargeOf && RD.chargeOf(...)`，
   守卫短路为假，**船员表单永不出现**（互斥探针实测 `crewRepair` 命中 0 次才暴露）。

3. **helper 插错了位置** —— 先插进 `STEPS` 对象字面量内部（那里不能声明 `const`），
   改插到 `createSteps` 函数层。
4. **替换脚本切掉了残留行** —— 一处 `kind:` 表达式与一行 `targets:` 被误删/误留。

   p.repairValue = null;`（全体玩家），且我插了两次。已删。
9. **探针自身的三处判据错误**（都造成假违例，已在文件注释里留档）：

## 八、一个既有缺陷：死囚的复生表单缺失（裁定①②的副作用暴露）

**这是本批最有价值的副产品**，必须单独说。

- **症状**：步骤 8 的 `req` 对死囚可推出 `kind='revive'`（6.8.4 复生，条件
  `role=convict` 且 `reviveLeft>0` 且场上有濒死者），但 `form` 的首行判
  `isClassicXeno(p)`，死囚 `role` 不是 `xeno` ⇒ 落到医生分支返回 `kind='doctor'`；
  **`form` 根本没有 `revive` 分支**。于是死囚被静默塞进医生表单，能拿到治疗／救援／制药／毒药，
  而真正的复生能力无法发动。与 43 号注释描述的外星人那次是同一类病。
- **确定性复现**：`tools/probe-revive-kind.cjs`（就地构造死囚本体形态，不跑随机对局）。
- **先于本批**：在 `8dd0d17`（voice 批次，早于裁定①②）上跑**同一探针**，同样
  `req=revive` / `form=doctor`。⇒ **不是本批引入。**
- **本批为何突然变红**：裁定①把自我治疗额度改为「有感染标记才到账」，外星人在步骤 8 的
  派发变少 ⇒ 取随机次数减少 ⇒ `g.rng` 整条流移位 ⇒ 这个潜伏缺陷在随机对局采样里被撞了出来。
- **方法论教训**：**随机探针对这类缺陷不可靠**（流一动就变红/变绿），确定性探针才靠得住。
  随机采样那条断言后来自己又变绿了 —— 这恰好印证了它不是可靠的检测手段。
- **断言处置**：没有削弱它。在 `test-fix-v26.cjs` 新增**独立的** `__V7_PRESURFACED__` 登记表
  （与 `__V7B0_VOID__` 分开记：后者是「被测对象已归档、覆盖消失」，前者是「对象存在、
  断言正确，但查出的缺陷先于本批」；混记会把「查出了真 bug」误读成「测没了」）。
  同时把「死囚O」断言拆成两条：**覆盖量**（`checked > 200`，真判）与**一致性**（按既有缺陷登记）。
  拆分理由：原断言把「样本够不够」与「有没有不一致」压在一个 `cond` 里，若整体停跑，
  连「探测器有没有真的在跑」也一起失去覆盖。
- **为什么没顺手修**：修法是给步骤 8 的 `form` 补 `revive` 分支，但那会改死囚行为
  （当前它错误地拿到了医生技能）。超出本批裁定①②的授权，**登记待办，未做**。
- 登记在 `IMPL_GAP['convict.revive.form']`，含复现命令与影响说明。
