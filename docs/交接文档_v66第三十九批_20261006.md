## 〇、三句话

1. **版本真源**：版本号不再散落，改由根 `package.json` 独家持有——`version`（`2.0preview`）供页面/README/文档显示与 APK `versionName`，`androidVersionCode`（`2`）供 APK `versionCode`；`tools/pkg-field.cjs` 是唯一的读取入口（批处理里内嵌 `node -p "require(…)"` 会被仓库中文路径和 `for /f` 转义坑到）。
2. **APK 重打包**：`SpaceKill.apk` = **4,473,343 字节（4.27MB）**、`versionName=2.0preview` / `versionCode=2`、签名沿用旧 keystore（证书 SHA-256 `29ad3df4…`，用户可覆盖安装）。文件名保持不带版本号，下载 URL 永不死链。
3. **manifest 不再声明版本号**（关键修法）：`aapt2 link` 的 `--version-code/--version-name` 会被 `AndroidManifest.xml` 里显式写死的同名属性**静默覆盖**——首轮构建日志打印 `versionName=2.0preview`，产物却仍是 `1.0.0`。删掉 manifest 里的版本属性后版本才真正生效，该约束已进 §32 回归断言。

## 四、备注 / 坑

- **cmd 调 build.cmd 必须用绝对路径**：在 PowerShell 里 `cd 项目; cmd /c "android\build.cmd"` 会以工作区根为CWD 解析，报「系统找不到指定的路径」；用 `cmd /c "<项目绝对路径>\android\build.cmd"`（脚本内部全用 `%~dp0`，不受 CWD 影响）。
- **APK 体积 1.4MB → 4.27MB**：主因是批38 换入的 `music-bgm.m4a`（3.58MB，未压缩进包）。作品集卡片上的「1.4 MB（v1.0.0）」文案本批已随之更新。
- **XML 注释里不能出现 `--`**：manifest 注释里写 `--version-code` 会让 aapt2 报 `not well-formed (invalid token)`，措辞须改成「versionCode / versionName」。
- 版本不持久化到 localStorage：刷新后音乐速度回到 ×1.00。
- `versionCode` 必须每次发布递增，否则同签名也无法覆盖安装；已由 §32 断言守住「必须存在且 ≥1」，递增仍靠人。
