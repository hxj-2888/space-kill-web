## 三、最值钱的部分：本批的坑（每个都进了断言或注释）

1. **随机流纪律（红线 3 的实时版）**：实时点击若即时结算，`g.rng` 的抽取顺序就变成玩家手速。
   `SKActions.flush` 按 **tick → 房间 → 玩家编号 → actionId** 固定键排序 —— 换排序 = 复盘/蒙特卡洛全废。
2. **tick 边界**：`dueTicks` 最初把"刚开始的 tick"也算完成，0.5s 会出 3 个 tick。
   正确口径是"tick **走完**才到期"（0.5s = 2 个）。错一次，整局结算次数多 1/3。
3. **斜廊的门内死缝有两层**：
   ① 沿 45° 延长 2.6 格在 y 轴只有 1.84 —— 必须**按 `max(|ux|,|uy|)` 折算**延长量；
   ② 即便如此，走廊圆形扫掠与房间内缩矩形之间仍有 **0.04~0.13 格的细缝**（A* 化简后的折线正好踩上）
   —— 最终解法是每个门锚点铺**轴对齐门洞垫片**（沿墙 ±1.15 廊宽 / 向房内 2.6 / 向廊侧外延 1.2），
   与走廊角度无关。这条是米字布局能不能玩的关键。
4. **SH19 的"门内 1.2 格"测不出死缝**：廊半宽 1.3，1.2 < 1.3 会被糊过去。改成 **1.8** 才真正有牙齿。
5. **`segHitsRect` 旧实现拿包围盒比**：轴对齐线段没事，斜段误报"穿房"。已换 Liang–Barsky。
6. **变异会打错文件**：搬代码后 `selfcheck` 报"变异未命中"≠ 断言空转，是变异还打旧文件
   （SH8/S3a → shell.js、U2A2/T2 → crew.js、SH3/SH5 → 新字符串）。两者都要报出来。
7. **没有 `doctor` 角色键**：医生是 group（成员 bio/vaccinist/rescue/poisoner）。
   用 `role:'doctor'` 测试会让 `hasGrant` 全 false，看着像闸门坏了。
8. **能力有两套表达**：`grants`（授权数组）与 `charges`（额度键，例 `crew.charges.assistRepair`）。
   闸门/校验必须两套都认；`crew` 没有 `repair` grant（协助维修走 charges）。
9. **SH26 的教训**：断言只查 `clockHtml` 里有没有"问时钟"，把刷新那行写死 `'0:00'` 仍然全绿 ——
   **首渲染与定时刷新两处都要问**（数出现次数 ≥2）。
