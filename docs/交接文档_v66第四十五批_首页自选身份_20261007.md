## 一、范围与拍板

来源是《提示词 A · 前端优化方案》§二「角色选择界面」。该方案的其余条目（等比 rem 缩放、
夜晚决策区、事件结构化、三路音量等）**不在本批**：横向移动等比缩放方案已在批 42 评估并否决
（会重写 1300 行 CSS 并使两个 Playwright 门禁失效），其余条目与本次诉求无关。

开工前就两个岔路口征得拍板：

| 岔路 | 拍板 | 理由 |
|---|---|---|
| 玩家点了变体角色但本局掷出另一变体 | **强制按选择掷出** | 单机只有玩家一人选，不存在抢位；让它 50% 概率拿不到自己点的角色是纯挫败。方案文档的「回落」示例理由是「该角色本房已达上限」，那是多人房间的场景，单机不存在。**席位数一字未动**（猎杀位仍是 1 个，只是 occupant 由警长换成猎手），不违反 2.3.0②附二。 |
| 未解锁角色置灰 + 解锁进度 | **先不做，接口留好** | 项目没有任何养成/进度系统，门槛数值无从谈起。改为在声明层放一张全 `null` 的 `ROLE_UNLOCK` 表，日后加门槛只改这一张表。 |

## 二、实现

### 数据流：单向，无第二份真相

```
roleDecl（角色/组位/席位/可选性）
   └─> ui.js rpRoleList()  现场派生角色清单 ─> #role-grid 卡片
                                              │
玩家点选 ─> RP_STATE.role ─> preferredRole() ─> main.js
                                                        │
                                    Setup.rollSeatPicks(seed, preferRole)   ← 钉死该席位变体
                                    Setup.createGame(seed, pref, {seatPicks, preferRole})
                                                        │
                                              g.roleWanted / g.roleGot / g.roleNote
                                                        │
                                          banner（立即可见）+ priv（永久记录）
```

`ui.js` 不含任何角色字面量 —— 加角色只改声明层（K1 纪律）。可选性读
`SKRoleDecl.selectable`，组位读 `GROUP_TABLE`，变体归属读 `Setup.seatClaim`。

### 双向联动

- 选身份 → 阵营卡片自动跟随该身份的阵营（身份是更强的信号）
- 改阵营 → 已选身份不属于该阵营就清空并 toast。**「随机」一律清空**：随机意味着连阵营
  都不定，留着具体身份偏好会让人以为开局一定是那个身份。

### 面板形态

沿用 `#rules-overlay` 的覆盖层结构（`fixed + inset:0 + z-index:60`），**不自造 `.modal`
体系** —— 两套弹层在同一屏上，点击穿透与 Esc 行为会分叉，而它们的关闭手势必须一致。
Esc 关闭也按规则速览的既有手势接上。

## 三、关键实现细节（踩过的坑）

### 1. 锁定席位时**必须照常掷骰**

第一版写成「锁定席 `continue`，跳过 `r.next()`」。后果：被锁席位之后的序列整体前移，
**「玩家选了猎手」会连带改变工匠 / 窃听者 / 毒师 / 死囚出不出现**。

正确写法是锁定只改**取值**、不改**是否掷**：

```js
const hit = r.next() < 0.5;                                   // 每席都掷
if (claim && claim.seat === from) {
  if (claim.variant === 'B') picks[from] = SEAT_VARIANTS[from];
} else if (hit) picks[from] = SEAT_VARIANTS[from];
```

这样每席结果只由（种子, 盐, 席位序）决定，玩家的选择**精确地只影响他选的那一席**。
门禁 自选L / 自选M 守的就是这条（注入验证见 §五）。

### 2. A/B 两侧都要钉 —— 只认 B 会让「选变体 A」有一半概率拿不到

第一版的 `seatOfVariant` 只反查「谁是变体 B」，于是：

```
选「警长」（变体 A）→ 不触发任何锁定 → 猎杀位仍 50/50 掷骰
                    → 实测 200 局只有 105 局拿到警长，另外 95 局变成猎手
```

玩家点 A 却换成了 B。改为 `seatClaim(roleKey)` 同时产出两条记录（变体 A 与变体 B），
实测 15 个可选角色在 60 局里**全部必中**。

### 3. 回落文案必须区分两种「没给到」

```
变体席位未掷中 → 「你自选的「猎手」本局未出场 —— 同席位掷出了变体「警长」…」
角色键不在席位表内 → 「…不在本局席位表内（转职系职业只能经步骤 0.6 获得）…」
```

第一版对两者一律写「不在本局席位表内」。对变体角色这是**错误归因** —— 席位表里明明有它，
只是这一局没掷出来。门禁 自选P 专守这条。

### 4. 提示走两个通道（生命周期不同，不是重复）

- `banner` —— 立即可见。沿用寂灭/决斗/停转夜横幅的既有约定。
  配置类提示不该藏在「私人」标签里等人去找。
- `priv` —— 永久私人记录，复盘可查。

且必须在 `Engine.begin` **之后**发：`begin` 会公告批次〇并建立队列，插在它前面会让这条
提示排在开局公告之前，读起来像上局残留。

### 5. 解锁门槛接口（当前全解锁）

`roleDecl.js` 新增 `ROLE_UNLOCK` 表 + `unlockOf(k)` / `selectable(k)`：

- 全 `null` ⇒ 当前没有任何角色被胜利数门槛锁住
- `transferOnly: true` ⇒ 转职系（临时医生 / 助理工程师 / 武装船员），只能经步骤 0.6 获得，
  **绝不外露到自选面板**
- `ui.js` 的 `rpCardHtml` 已按 `unlockOf` 写好 `disabled` + 门槛文案分支，日后设门槛只改表

面板 HTML 与 `ui.js` 都预留了 `.rp-card.locked`（`opacity + pointer-events:none`）样式。

断言的是**真实渲染与真实点击**，不是源码 —— 面板是覆盖层、卡片由 ui.js 现场派生，
任何一处选择器或类名漂移都会让它整块失效而源码看着没问题。覆盖 6 个视口：

```
✓ iPhone 14 横屏 844×390（自选身份 15 卡 / 3 列 / 卡高 117px）
✓ iPhone SE  横屏 667×375（自选身份 15 卡 / 2 列 / 卡高  96px）
✓ Android    横屏 915×412（自选身份 15 卡 / 3 列 / 卡高 101px）
✓ 桌面       1440×900（自选身份 15 卡 / 3 列 / 卡高 132px）
```

含：面板可开合、角色数与声明层一致、转职系不外露、每卡有名称与说明、点选后 chip 与
阵营联动、清除按钮的出现与复位、面板不撑破视口宽、内部可滚、卡片触摸高度 ≥60px。

⚠ 门禁末尾会把选择复位成未选态，否则这一档的选择会漏进后面的相位扫描。

## 七、代价与遗留（如实记录）

**首页在矮屏上多了一行要滚。** 实测：

| 视口 | 卡片内容高 | CTA 需下滚 |
|---|---|---|
| 844×390 | 539 → **605** px | 404 → **470** px |
| 1440×900 | 900 → 900 px | 无需滚动（本来就不滚） |

即：矮屏横屏下 CTA 本来就在折叠之下（404px 是既有状况），本批加了 66px。
**身份行本身落在首屏内**（top=340，视口 390），不用滚就能看到并点开。
这 66px 里有 40px 是触摸目标高度（手机横屏热区保底），压到 32px 能省 8px，
但不值得牺牲指尖命中面积，故保留。矮屏本就设计为「页面不滚 + 卡片内滚」（批 42 的口径）。
