## 〇.5、批 43 · 主区按阶段自适应

**问题**：`#chatlog` 与 `#stage-body` 是两个**常驻** DOM，各占一半高度，与当前阶段无关。夜里没有公开发言，发言区照样占着半屏（显示「暂无公开发言」），真正要看的私聊 / 决策 / 公告报告被挤在半屏里。

**改法**：两处包成可整体显隐的区域 `#region-chat` / `#region-dec`，由 `UI.stageLayout(g)` 裁决四个布局键写入 `#seg-stage[data-layout]`，CSS 按键分配高度。

| 键 | 触发 | 发言区 | 流程区 |
|---|---|---|---|
| `talk` | `g.pending.stream`（D-open / D-talk / M-talk / M-speech） | **主**（flex 8） | 副（flex 2） |
| `day-form` | 白天 + 待决策表单（D-vote / D-will / D-report） | 副（flex 3，**不隐藏**） | 主（flex 5） |
| `day` | 白天自动步骤 | 主（flex 7） | 副（flex 3） |
| `night` | `g.phase === 'night'`（**不论有无表单**） | **display:none** | 全部 |

三个判定要点：

1. **`talk` 优先于 `phase`。** 步骤 10 紧急会议（`M-talk` / `M-speech`）在 `phase === 'night'` 期间，但它本质是讨论窗口 —— 若按 phase 收起发言区，玩家会看不见自己正在讨论什么。
2. **`day-form` 不隐藏发言区。** 投票时要对照刚才的发言；只有夜间才整体收起（夜间 `chatLog.filter(t => t.night === g.night)` 本就为空，留着是一块永远写「暂无公开发言」的死区）。
3. **收起用 `display:none`，不是 `height:0`。** 空盒子仍占边距，且移动端手势/焦点可能落进不可见区域。

**顺带补的两处**（缺了它们，收起发言区就成了功能退化）：

- **「今夜私聊」小结**（`ui.js: nightChatHtml`）：夜间主区只剩流程区，玩家此刻最想回看的就是自己那几句私聊。此前只能翻右栏「私人」页签。数据源 `g.nightChats` **只取含本人的配对组** + `p.inbox` 的私聊/队内条目 —— 批次①只公告「谁和谁配对」，正文不公开（2.2），故绝不渲染他人配对组。
- **右栏「发言」页签**：`renderSide` 的 `tab === 'speak'` 分支本就存在但**无入口**。补上按钮后，白天讨论全文在夜间仍可回看。

**实测（真实对局推进到指定步位，Playwright 量测）**：

```
desktop 1440×900   night/0a 4a 9 10 → night，发言区收起，流程区 fill 99%，真留空 8px
                   day/D-vote      → day-form，发言 270px / 流程 458px
                   day/D-talk      → talk，发言 575px / 流程 153px
phone   844×390    同 6 态          → fill 95~96%，真留空 8px，JS 错误 0
```

那 8px「留空」是 `.input-dock{margin-top:8px}` —— 常驻 chrome，不是空区。

**过程中被门禁抓出的一个真 bug**：极矮横屏下 `day-form` 把发言区压到 **54px**（844×390 投票时）。原因是 `min-height` 只加在了 `.chatlog` 上，而 `.chatlog` 的父区域 `.region` 仍会被 `flex-shrink` 压到比它更小 —— 结果 `.chatlog` 溢出被裁。**地板必须加在区域（flex 子项）上**。现为 `min-height:118px`（= 标题 33 + 发言区下限 84），`talk` / `day` 同样加。

**验收分层**（这次刻意分开，因为 Node 断言跑不了 DOM）：

| 层 | 位置 | 断言什么 |
|---|---|---|
| 结构 / 接线 | `test-fix-v26.cjs` §42.6（16 条） | 区域节点、`data-layout` 预置、两个导出、四个键、夜间不看 `pending`、`talk` 优先、私聊只取本人、`renderChat` 收起时仍推进 `_total`、CSS 四键规则与 118px 地板 |
| **行为 / 量测** | `mobile-layout-check.cjs`「主区相位扫描」（6 态 × 5 档视口） | 夜间发言区真的 `display:none`；流程区占满可用高度 ≥90%；发言区保留时 ≥70px |

门禁**直接调 `UI.applyStageLayout`**，不复述判定逻辑 —— 避免「门禁和实现各写一份、两边漂移」。

## 五、可见性收口的设计要点（后来者必读）

1. **单机与联机必须共用一个出口。** `view.js` 头注释里写着「本文件是唯一的视图构建器」，但单机路径从未调用它 —— 架构意图早就写好了，只是没接上。本批接上后，`auditView()` 对单机同样生效。
2. **`auditView` 的 B4 检查一度恒报 14 条噪声**：`hydrate()` 会给每个玩家补 `known = new Map()`，而原判据把「空容器」也当违规。空 Map 不携带信息，B4 要禁的是**有内容的**他人私有节点。
3. **跨 realm 陷阱**：`test-fix-v26.cjs` 的 `ctx` 是 vm 沙箱，vm 内构造的 `Map`/`Array` 与测试文件 realm 不同，`instanceof` **恒为 false**。判定容器一律用 duck-typing 或 `Array.isArray`。
4. **医生视角的正确形状**：`{exists:true}`（4.5 真伪不可辨）；异形队友 `{exists:true, real}`（3.3④ 可辨真伪）。用 `infection.real !== undefined` 判定泄露即可同时覆盖两个方向。

## 六、遗留与建议

- **主区未按阶段重构**：`.chatlog` 与 `.stage-body` 仍是常驻 DOM、各占一半高度，与阶段无关（夜里无发言时主区留空）。这是外部方案里**唯一结构上成立**的前端条目，但改动面大（涉及 `renderStage` / `renderChat` / 表单通路），本批未做 —— 建议单独一批，且必须保住 `#talkbar` 在非发言阶段**移出 DOM**（否则移动端键盘会残留高度）。
- **等比 rem 方案未采纳**：项目走 px + 三档断点，且有 Playwright 门禁守着。改 `html{font-size:min(...)}` 等于重写 1300 行 CSS 并使现有两个门禁失效。建议维持现方案，只按需加断点。
- **胜率基线已变**：变体局混入后 120 局读数 `人类 39% / 异形 44% / 外星 17%`（经典局基线 `27.2% / 59.6% / 13.2%`）。样本小、且变体机制本就改强度，**不要据此调权重**（见交接文档 §3 红线）；需要读数请跑 `tools/mc.cjs 500 1`。
- **500 局蒙特卡洛基线尚未覆盖变体局**：`mc.cjs` 不传 `seatPicks`。若要把变体局纳入平衡观测，需给 `mc.cjs` 加 `SK_SEAT_VARIANTS=1` 开关并分叉基线。
- **角色偏好 API 未做**（按拍板）：单机下它只是本地参数，可在 `main.js` + `state.js` 内实现（软偏好 + 冲突回落 + `fallbackReason` 文案），不引 REST。等联机真正上线再做服务端。
- **`⑫` 是死代码**：`ui.js` 的 `BATCH_CLS` 里 `'⑫':'b12'` 无对应产出步骤，可删。
