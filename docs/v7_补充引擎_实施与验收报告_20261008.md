## 一、补的三处（全部卡上明写）

### 补 1：外星人「自我治疗」不赋予抗体

**卡两处明写：**
- §外星人·核心能力：「自我治疗：清除自身感染并**赋予抗体**，占用当夜行动名额」
- §v6.5 修订要点⑩抗体赋予：「主体依 3.3.9：生化医师的治疗与自救、**外星人的自我治疗**；救援医师／临时医生不赋予」

**引擎现状：** `steps.js` 自我治疗结算只调 `clearInfection(g, p)`，**不写 `antibodyNight`** ⇒ 自我治疗后下一夜不再抵挡感染。

**处置：** 补写 `p.antibodyNight = g.night + 1; p.antibodyBy = p.id;`，与生化医师两处（`steps.js:1378/1408`）**逐字一致**，故到期与层序判定（`engine.js applyInfection`）自动适用，无需另写。

**不发「抗体生效」私反馈**：卡的私人反馈六类（7.2.1~7.2.6）没有这一项，该措辞只出现在**生化医师可见性**行；`engine.js:187` 的 `b.role === 'bio'` 门控**保持不动**。

### 补 2：`cureSelf` 无到账点 —— 自我治疗整个机制是死代码

**全仓核验（4 处，无一赋正值）：** `state.js:40` 初始化 0 · `steps.js:285` 使用后置 0 · `steps.js:1211` req 读 `>0` · `steps.js:1336` 结算读 `>0`。

⇒ req 与结算两处分支恒不命中，**自我治疗永远不可用**。

**卡的口径：** 外星人「额度」行**未列**自我治疗（该行只有夜晚免疫 2 次／破坏全局 1 次／觉醒后每夜至多 2 刀／乔装全局 2 次）；卡只说它「占用当夜行动名额」，且封锁通则明写「感染抑制与自我治疗行使后当夜丧失其余主动行动能力」⇒ **当夜上限由行动名额给出，不是独立计数**。

**处置：** 在 `engine.js` 夜间到账区（与警长子弹、外星人夜晚免疫同一块，无条件分支）加一行
`if (p.role === 'xeno') p.cureSelf = 1;`
到账即用尽，当夜第二次仍被行动名额挡住，**不可能一夜两次**。

> ⚠ **卡未明写额度，此为推断。** 已登记 `roleDecl.IMPL_GAP['xeno.cureSelf'].openQuestion`。
> 若正文另有终身 N 次口径，只需改两处常量（`engine.js` 到账行 + `roleDecl.charges.cureSelf`），
> 机制与 req/结算分支不动。

### 补 3：毒师开不了制药

**卡（毒师条·夜间行动）：**「步骤 8：制药 ／ 毒药 ／ 解药 ／ 制药产出的救援 ／ 治疗——五选一（毒师无自救额度）」；制药为医生族通有（3.3.1）。

**引擎现状：** `processRegistry.brew.owner = ['bio','rescue','tempdoc']` —— **未含 `poisoner`**，尽管上一轮已依卡把 `'brew'` 补进 `ROLE_DECL.poisoner.grants` ⇒ **声明说能制药，进程引擎不认**。

**潜伏性：** 医生位开局席位固定 `['bio','rescue']`（2.8.14 组位表 capacity 2），毒师不上场故此前不可观测；席位表一旦改为三选一即暴露。

**处置：** `owner` 补 `'poisoner'`。

## 二、确定性验证（不依赖随机对局，`tools/verify-cureself.cjs`）

直接构造状态 → 调引擎 `STEPS['8'].req` → 提交 → 查三件事。**5 项全通过：**

| # | 检查 | 结果 |
|---|---|---|
| ① | 额度到账：进入本夜后 `xeno.cureSelf` | **1** ✓ |
| ② | 步骤 8 req 派发（有感染 + cureSelf=1 + 未行动） | 返回 `["xenoCure@4","doctor@5","doctor@7"]` ✓ |
| ③ | 结算：感染清除 + 写抗体 | `infection = null`，`antibodyNight = 2`（= night 1+1），`antibodyBy = 4` ✓ |
| ④ | 抗体拦截（授予夜 **+1**，抗体在场） | `applyInfection` 返回 `blocked`，感染**未落地** ✓ |
| ⑤ | 抗体时效（授予夜 **+2**，抗体已过期） | 返回 `real`，感染**正常落地** ✓ |

> ④⑤ 精确验证了卡的「时限型」语义：「仅存在于获得后的下一个夜晚，该夜内抵挡 1 次感染，
> **夜末一律失效、不结转、不累积**」。

**过程中我自己写错过一次**：第一版验证在授予当夜就施加感染，读到 `real` 而判「失败」。
实际是我的构造违反卡的时限语义（抗体在**下一个夜晚**生效），修正后 ④⑤ 全通。原始读数与修正
都留在 `tools/verify-cureself-result.txt`。

**另一处诚实修正**：`tools/verify-supplement.cjs` 在 120 局随机对局里读到「自我治疗 req 派发 0 次」。
那不是补丁失效 —— 外星人在随机局里很少被感染到感染。故改用上面的**确定性构造**验证，不拿随机局
当判据。
