## 二、视野方案（提案，未实现）

### 2.1 模型：房间亮度 × 手电锥形

```
每间房 / 每段走廊有一个 light 状态：
  · 亮（应急灯正常）：会议室 + 4 间正房 + 全部走廊
  · 暗（常态灯坏）：4 间斜房
  · 事件亮/闪：破坏进行中（红闪）、会议强制全亮

「我」的可见范围 = ∪
  ① 我所在房间若是亮房 ⇒ 整间房可见（含屋里的人）
  ② 手电锥形：以我为原点、朝移动方向张开的锥形
     · 锥角 60°、锥长 7 格（可调）
     · 周身微光半径 1.5 格（不然连自己的手都看不见）
  ③ 以上全部 ∩ 不跨墙（losClear 不变）
```

### 2.2 关键推论（这就是玩法）

| 情形 | 结果 |
|---|---|
| 我在亮房，目标也在亮房 | 互相看得见（无遮挡即可）—— **想杀人的必走亮区** |
| 我在暗房开手电 | 我照亮一锥，但**锥形本身就是"我在这里"的广播** |
| 我在暗房关手电 | 只剩 1.5 格微光：几乎看不见路，但别人也看不见我 |
| 目标在暗房且不开手电 | 我看不见他，他也看不见我 —— **暗房是盲区博弈** |
| 异形夜视？ | **不给**（见 §四 待定 3）：暗房对所有阵营一视同仁，否则"暗"失去意义 |

### 2.3 与旧方案的关系

- **替代**旧的"半径 9 圆"（不是叠加）。`VISION_R=9` 退役，
  换成 `cone{angle:60, range:7, halo:1.5}` + 房间 light 状态；
- `inSight(from,to)` 的**函数签名不变**，内部换成"亮房 ∪ 锥形 ∩ losClear"——
  R1 定下的"AI 目击必须调同一个函数"继续成立；
- 枪的射程 = 视野：亮房内被房间尺寸截断，暗房里锥长 7 格
  ⇒ **暗房里枪打不了 7 格以外的目标**（手电照多远打多远）。

### 2.4 实现载体（估算）

SVG `mask`：黑底全屏 + 白色亮形（亮房矩形 ∪ 锥形多边形 ∪ 微光圆），
盖在场景层之上、HUD 之下。每帧只改 mask 的亮形三个元素（房间/锥/微光），
不动场景 DOM。角色若在 mask 黑区 ⇒ 天然不可见，**渲染裁剪逻辑可以完全删掉**
（R1 的"看不见不进 DOM"保留给 AI 目击用，渲染交给 mask）。

## 三、本轮已拆除（先破）

| 拆除项 | 内容 | 理由 |
|---|---|---|
| **点击人物呈现身份** | 点席位 → `openPlayerPop` 身份弹窗；pending 时点席位 = 代选目标并自动提交 | 人物只是"会走动的身体"；是谁要从机制推。点人物 = 走到他身边 |
| **移速** | 7.5 → **5 格/秒** | 走廊 2 秒穿完没有追逐感；跨房 12 秒，"赶路被看见"成立 |
| 私聊（UI 层） | 场景内已无私聊入口；面板里的"今夜私聊小结"与 invite/chat 表单将在技能重做批次随旧提交路径一起拆除 | 见 §五 顺序 |

## 四、待你拍板（视野方案落地前）

1. **锥角/锥长**：60° / 7 格是手感起点；要不要给"探照更远但更窄"的注视模式（按住 Shift → 30°/12 格）？
2. **暗房的门缝光**：门洞处漏不漏光（亮房的光从门缝漏进暗走廊 1 格）？漏 = 暗房位置可被推断，不漏 = 更黑。
3. **异形要不要夜视**：建议不给（见 2.2）；若要，只能给"暗房里微光半径 3 格"这种弱补偿。
4. **破坏与灯的联动**：破坏某间房的灯 ⇒ 该房变暗（异形的经典破坏项），
   要不要把"灯"纳入维修进度（M2 的进度条体系）？
5. **方位分配**：§一 的房间-方位表可整体旋转/对调，拍板后写进 `space.js` 注释。
