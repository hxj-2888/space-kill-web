### ③ AI 读法：感染排除**恢复**，濒死预筛**仍不做**

```js
const pool = ranked.filter(x => !x.x.infection).map(x => x.x.id);   // 排除已感染者 —— 有据
```

而濒死者**仍然保留在候选里、不预筛**，依据同样来自正文且更强 —— 5.3.1：

> 不可选濒死者（该限制**仅约束结算合法性**，UI 仍须依 4.10.4④ 将已濒死者保留在可选列表中，

## 六之二、同批后半段：把上面那条「第一优先」做掉了

§六 里我写「速查卡对账只覆盖『卡 ↔ 声明层』，不覆盖『正文 ↔ 卡』……本批证明这件事必须做」，

所以本批后半段把它做掉了。

### 新增 `js/v66/declaration/roleDecl.js` 的 `SENSE_SOURCE`

每条情报的出处写成**机器可核的结构**：`kind`（凭什么）× `clause`（哪一条）× `item`（哪一项）。

三种 `kind` 的区别是**授权的强度**，不可混用：

| kind | 含义 | 举证要求 | 计数 |
|---|---|---|---|
| `own` | 自身状态。正文不需明文授予（「自身状态，理所当然」，3.3.10② 即此口径） | 只需说清那个状态是怎么来的 | 9 |
| `granted` | 正文明文授予**他人**可见性 | **最严**：`clause` 写错或漏写就是 AI 比真人多知道一件事 | 16 |
| `derived` | 由已授权信息本地推导（已查验池、镜像账本等） | 出处是**推导所依据的那条授权**，不是新授权 | 4 |

举例：`infectMarks` 引 `3.3.10` 项 `①`（医生可见清单，不显真伪），
`infectMarksTrueFalse` 引 `3.3.10` 项 `④`（异形清单**且可辨真伪**）。
两者 `kind` 都是 `granted`，靠 `item` 区分 —— **这正是 3.3.10④ 的设计红线所在**。

### 新增 `tools/text-align.cjs`：双向对账

| 方向 | 拦什么 | 靠什么 |
|---|---|---|
| 正向（编造） | 引用了正文里不存在的条款号或项 | `SENSE_SOURCE` + 正文提取件 |
| 反向（漏项） | 正文里有可见性授权条款，声明层却没有对应 sense | 人工观察名单 `WATCH`（15 条，每条写明为什么在/不在） |

`WATCH` 刻意**不是穷举正文**（那做不到），而是把「已知的、容易漏的那几条」钉在案上：
每次出新的越界或新的授权争议都往里加一条，并注明它为什么值得钉。
红线条文（3.3.10③ / 5.3.1 / 6.8.4⑥ / 7.2.2 / 3.3.8）单列一节，标明**不应**产生 sense。

三条纪律（写在工具顶部）：① 只读只报，不改任何产品代码；② **不新增 sense 键** ——
新键＝新授权＝产品裁定，不是对账工具的权限；③ 提取件不在库，缺件时**报错退出而非静默跳过**，
否则「全绿」会变成「什么都没查」。

读法：`node tools/text-align.cjs <仓库根>` ⇒ `0` 无 P0 / `1` 有 P0 / `2` 提取件缺失。

### 现状

**29 个 sense 键全部可追到正文中真实存在的条款与项，P0 = 0。**

## 六之三、这个工具自己踩的坑 —— 全部是自检抓出来的，不是想出来的

一个从没报过错的检查器等于没有检查器，所以工具里带 `--` 自检（合成正文 + 9 条断言）。
它在上线前抓出**四个**真 bug，全部记在代码注释里：

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| 1 | `3.3.10①` 整体当条款号 | 正文里 `①` 是**条款内的项**，不是条款号的一部分 | `clause` 与 `item` 分开写，工具分别校验 |
| 2 | 平铺与偏移分开算 | `flat` 去空白、偏移却按 trim 后行长累加 ⇒ 行内那个空格被多计，越走越偏 | 平铺与偏移**同一次循环**里算 |
| 3 | 「取最短标题」被续行顶掉 | `6.8.3⑧克隆取得清洗）…` 标题只有 1 个字符，比真标题还短 | 标题以圈号/数字开头 ⇒ 是分项续行，不是标题 |
| 4 | 剥重复条款号的**顺序**反了 | `6.8.3 6.8.3 变形` 的 rest 是 `6.8.3 变形`，以数字开头 ⇒ 先判续行就把**真标题**丢了 | **先剥号、再判续行** |

坑 2 和坑 4 还有连带效应：重复条款号那行的平铺文本是 `6.8.36.8.3变形…`，
末位那个 `6.8.3` 正好落在 `from + c.length` 上，会被正则先命中。
若只排 `pos < from`，条款窗口立刻塌成空串。必须是 `pos <= from`。

坑 3 那条规则是我**先写错再改对的**：最初的判据是「同号多候选取最短标题」，
被自检的 `6.8.3` 用例打掉。写工具时最容易犯的错就是「挑一个看起来合理的启发式」，
而启发式必须能被反例证伪 —— 所以自检里专门放了那两种提取噪声当反例。

## 六之五、对齐收尾时顺手挖出来的东西：一个偶发崩溃 + 一个**时绿时红**的冒烟

跑回归时 `node tools/uismoke.cjs` 出现了一次 exit=1（"冒烟失败：1 处异常"），
紧接着重跑 5 轮共 150 局全绿。**一个时绿时红的冒烟等于没有冒烟** ——
红了没人知道是不是自己刚改的，绿了也不能证明任何事。
本仓库的验收规矩是「故意改坏实现必挂」；一个靠运气决定红绿的测试连这条都谈不上。

### ① 根因：用 `Math.random()` 挑选项

`tools/uismoke.cjs:56` 原本是：

```js
data.opt = ok[Math.floor(Math.random() * ok.length)].v;
```

同一份代码每次跑的路径都不同，于是「哪些代码路径被覆盖过」不可复现。
**改成可播种的确定性 LCG**（`SK_SMOKE_RNG` 环境变量可覆盖，默认 20261008）。
注意一个坑：uismoke 走 `vm/runInContext`，**host 的 `Math.random` 补丁对它无效**，
只能改它自己的源码。

### ② 确定性一开就抓到真崩溃：`js/ui.js:587`

```
TypeError: Cannot read properties of undefined (reading 'v')
  at renderForm (ui.js:587) ← renderStage ← render ← tick
```

`ui.js` 原本直接取 `f.num.options[0].v`。崩因是某一步的**必答项选项数为 0**：

| 位置 | 内容 |
|---|---|
| `js/v66/derivation/actions.js:169` | `verifyPool` 按 4.1.1③ 移除「全部真实持有者已出局的职业」 |
| `js/engine/steps.js:597` | `options: firstPool.map(...)` —— 池空则 `options` 为 `[]` |
| 表单文案 | 「身份①为**必答项**」⇒ 玩家被要求填一个**没有选项的必答项** |

触发态：所有**基础人类职业**都没有存活持有者（多名船员已转职的残局）。
复现：`SK_SMOKE_RNG=117`（或 120/135）+ 对局种子 912，稳定命中 4 次。

### ③ 修了 UI 崩溃，但**没有**替规则做决定

`ui.js` 改成防御式：空 `options` 时显式渲染「本项当前无可选项」并**不写 `formState`** ——
让提交走引擎自己的合法性判定，而不是在渲染层替它编一个默认值。

**「无可查身份时船员该做什么」是产品裁定**（只能放弃行动？还是池应回退到全职业池？4.1.1③ 怎么读？），
本批**没有替它决定**。改为把它变成**看得见的死面**：`uismoke` 每次命中都会打印

```
[死面] 必答项无可选项：crewAction.num ×4
      （不计入退出码：这是引擎面待裁定项，UI 与冒烟均已不崩。复现：SK_SMOKE_RNG=117 对局种子 912）
```

不计入退出码（那是引擎面的待裁定问题，不是渲染崩溃），但**必须打印** ——
静默自动跳过才是危险的那种处理：红绿都看不出来，"绿"会被读成"没有死面"。

### ④ 同一个空池也炸了冒烟本身
