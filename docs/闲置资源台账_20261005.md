# 太空杀 v6.6 · 闲置资源台账（第二十四批 · 2026-10-05）

> 目标：把「声明了但没人用」的东西**变成可审计、可交接、可清理的清单**，并给声明层加
> **声明-消费契约**，让这类漂移从「看不出来」变成「必须写明」。

---

## 0. 盘点结论（一句话）

**最大的一块闲置资源是通道库里的 462 条 dormant（91.3%）**，但真正的问题不是「多」，
而是**其中 38 条的判据所依赖的机制已被撤销或改值，它们在总表里与「只是还没接线」的
条目长得一模一样** —— 批次 19 接线时极易误接。本批把它们显式退役。

## 2. I2 · 判据失效台账（本批核心交付）

`js/corpus/channels.retired.js`（新增，独立文件，**不改 506 条总表数据**以保留与 v20 底本的可追溯性）

| 退役原因 | 条数 | 含义 | 复活条件 |
|---|---|---|---|
| `batch12` | **29** | 判据主体是批次⑫（医生清除感染出手公告），第十六批依 3.3.7 撤除该批次 | 批⑫若复原 → 从台账移除即活 |
| `ruleGone` | **2** | 判据依赖**已删除的机制**（第 1 夜被动全能免疫 → 限定技「安全室」，v6.6 2.3 表 #8） | 机制不恢复则永不成立 |
| `valueOld` | **7** | 判据引用的**数值已改**（警长子弹夜次、破坏档位、停摆档位） | ⚠ **不是死的** —— 判据仍可成立，接线时须按新值重写，**不可照抄 cond** |

**三方交叉保障**（新增 12 条断言）：
1. 退役条目必须全是 dormant（若某条已接线 ⇒ 台账过期，须立即复核）
2. 退役条目**不得有 gate 实现**（有实现 ⇒ 判据其实还成立，台账须修正）
3. 整局实跑后**无任何已判失效通道被触发**
4. 接线候选池 = `dormant 且判据未失效` ⇒ 剔除死判据后的真闲置

**执行器拒用**：`channels.run.js` 对 `batch12` / `ruleGone` 两类**硬拒**（即使误写 gate 也不执行）；
`valueOld` **不拒**（判据仍可成立，只是 cond 过时）。

## 3. I3/I4 · 声明-消费契约

`js/v66/declaration/roleDecl.js` 每个字段新增 `life` 标注：

| life | 含义 | 字段 |
|---|---|---|
| `wired` | 有运行时消费点，改动影响对局 | faction / actionStep / judgeMode / charges / attend / grants / capClass / repairExposeAt … 共 15 项 |
| `archived` | **合规留痕，运行时零消费** | `exempt` / `process` / `batchDelta` / `restatement` / `selfTarget` / `source` / `pending` |
| `pending` | 声明就位、等机制上线接线 | （当前为空） |

**新增审计**（`audit()`）：
- 每个已登记字段必须有合法 `life`
- `life:'archived'` 的字段**必须在 desc 里写明「零消费」理由** —— 否则报「闲置须有主」

**新增接口** `RoleDecl.idleLedger()`：输出 `{archivedFields, pendingFields, undeclaredRoles, orphanProcesses}`，可直接进交接文档。

### I4 特别说明：`pending` 命名陷阱
`ROLE_DECL[k].pending`（13/13 角色都有）与**对局状态 `g.pending`（待决策席位）同名但完全无关**。
全仓 20 处 `g.pending` 读取**没有一处**读的是角色声明 —— 这是极易误接的陷阱。
已在字段 desc 里写明警示，并有断言锁死。

## 4. 明确不做的事（附理由）

### CSS 死选择器：**放弃清理**
静态扫描出 50 个「零命中」类选择器，但逐一复核发现**绝大多数是假阳性**：

| 类名 | 实际来源 |
|---|---|
| `.talking` / `.me` / `.out` / `.nom` | ui.js 模板字符串拼接（`class="pl ${...} ${p.out ? 'out' : ''}"`） |
| `.b1`~`.b12` | 对象字面量映射（`'③': 'b3'`） |
| `.neg` / `.pos` | 三元表达式（`e.delta < 0 ? 'neg' : 'pos'`） |
| `.f-h` | 阵营类名前缀 |

**真正的死选择器只有 5 个**（`.hud-item` / `.chatbox` / `.layout` / `.idn` / `.skull`，
共 11 行），但它们与 v33/v34 的 `.seg-*` 布局是**同源重构的旧版**——静态判定不足以安全删除，
且 UI 改动的回归成本远高于收益。**故本批不动 CSS。**
