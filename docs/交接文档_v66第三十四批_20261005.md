## 一、注意力选择化

### 1.1 三层结构（此前只有两层）
| 层 | 字段 | 语义 | 例 |
|---|---|---|---|
| 主业 | `attend` | >1，这件事我格外上心 | 工程师 infra 1.30 |
| **非主业** | **`attendAway`（新增）** | **<1，这件事我不太关心** | 工程师 lethal 0.70 |
| 缺省 | — | 1.0，不特别关心也不特别忽略 | 工程师 ballot 1.00 |

### 1.2 floor 闸门
`roleDecl.ATTEND_FLOOR = 0.8`（声明层常量，可标定）。`moe.absorb` 在写入侧：低于 floor 的 claim **不进账**（`stats.ignored` 计数），而非以弱证据入账。

**三条纪律边界（§27.1 断言把守）**：
- 未归族事件（w=def=1）恒过闸 ⇒ 行为不变；
- 私有源走 `absorbPrivate`（红线 3：该角色必入账），**不经此闸门**——自己的私有体验不能因「注意力低」而不被自己记得；
- 硬源走 `project` 短路，天然不经 absorb。

**宣称族（verify）的特殊处理**：自称是**公开可核验**信息，「不关心」不等于「听不见」——那是感知缺失，不是注意力。故 `attendAway.verify` 恒 ≥ 0.85（高于 floor）。此条由门禁断言强制（首版把四个角色设为 0.75，会被闸门拦掉自称入账，已修正）。

### 1.3 实测
30 局：floor=0 丢弃 0 条 / floor=0.8 丢弃 11158 条；加权入账 42808 → 35533 条。

## 二、系数标定（`tools/attend-ab.cjs`，`npm run probe:attend`）

严格按 `docs/防指标博弈治理规范.md`：单变量、验证集 101+（与指纹集零重叠）、分阵营、只读不进 gate、如实报告恶化项。

**基线读数**（验证集 101-220，120 局）：

| 指标 | 读数 |
|---|---|
| human 开局 / 中期 / 残局 | 0.412 / 0.456 / 0.508 |
| **非异形合计（主判据）** | **0.432** |
| xeno | 0.415 |
| alien（对照，不作判据） | 0.522 |

**单变量 A/B 结论**：floor=0（关闭选择化）与 floor=0.8/0.9 读数**完全相同**（0.432）——**注意力选择化对 AUC 中性**。

**如实说明两点**：
1. 该结论的前提是「选择化只改变证据的**有无**，不改变判断**排序**」——机制正确性得到确认，但不是性能改进；
2. 主判据 0.432 **低于随机线 0.5**，与 cloud-ab 早前测得的 0.527 方向相反。二者口径不同（本探针逐夜逐观察者取一个 pos-vs-neg 全集 AUC；cloud-ab 另有采样时点），**不可直接比较**。此项已列入待裁决（§五）。

## 三、性格影响判断

`traits.baseDanger`（25→30 / 50→50 / 75→70）此前**零读取点**——「保守档对同一危险源的判定值更低」从未生效，性格只影响表达。

现接入 `belief.dangerOf`：`dg += (baseDanger[θ] − 50) × DG_W.act × 0.5`。

**关键设计**：同一 θ 的所有目标**同步平移** ⇒ **不改变任何目标间的相对排序** ⇒ 不影响「谁更可疑」的推理质量，只改变「多危险才值得动手」的阈值心理。§27.2 以「θ 档内目标间极差未被压缩」断言把守——若误做成按目标缩放，极差会被整体压缩。

此前 traits.js 自己的注释「性格只经阈值+容忍两条路径传导，不调制客观量」也随之修正：v21 改动 #6「τ 固定」的初衷是禁用手写 per-player 常数漂移，而非禁止由**声明层统一给出**的性格基线。

## 四、叙事层 N2：复盘 UI 挂载

复盘盒加「原始／叙事」并排页签（`index.html` + `ui.js` + `style.css`）：

- **默认原始**——叙事是增量视图而非替代，可随时回退，不改原始数据；
- 叙事页签含两段：**你的视角**（`Narrator.voice`，含长期记忆与立场收尾，暖色标示主观）＋ **全局编年**（`Narrator.renderDoc`）；
- 纪律：①纯读，不改 `g.replay`/`g.log`；②逐字转义后插入（与原始流同一防注入口径）；③生成失败降级为提示文本，**不阻断终局**；④叙事页签忽略夜次筛选（叙事是整局连贯叙述，切夜会破坏因果链）。

**⚠ 联机态本批封锁，只留备注不实装。** 叙事页签当前**只在单机局成立**。联机局 `Game.g` 是 `View.hydrate(m.view)` 的视图而非真对局，而视图的 `log` 经 `SKVisible.canSee` 按观察者过滤（`view.js` build），故：① `chronicle()` 读到的是「该玩家能看到的编年」而非终局全知编年——**静默降级**，同一局在单机与联机会讲出两份不同的复盘且不报错；② `duelSinceNight` 不在视图载荷内，决斗章节标注回落 `g.night`；③ `mem`（AIMemory，内部为 Map）不过线（AI 跑在服务端），`voice()` 拿不到长期记忆，联机局只有「全局编年」段、无「你的视角」段。解冻时须给视图补一份不过 `canSee` 的编年源（或由 server 在 `end` 载荷直接下发 chronicle 结果），并裁定 `voice` 是限定单机还是随载荷下发。完整备注见 `js/ui.js` 复盘盒 N2 段。另注：`tools/uismoke.cjs` 只跑 `startLocal`，**联机态零覆盖**，上述分叉无任何测试会抓到。
