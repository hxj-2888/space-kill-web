## 〇、三句话

1. **手机此前根本玩不了**：`#screen-game{min-width:1080px}` + `.board{min-width:1020px}` 是桌面硬下限，手机横屏（844×390 / 667×375）点「开始」就进不去对局 —— 而 APK 已在分发。现改为：横屏矮屏解除下限、三栏 → 单列中栏、名单改顶部横向滚动条、侧栏改右侧抽屉；竖屏明确提示旋转。
2. **App 启动即横屏**：`MainActivity` 加 `android:screenOrientation="sensorLandscape"`（跟传感器但锁横屏），玩家不再先看到竖屏提示。`configChanges` 已含 orientation|screenSize，旋转不重建 Activity。网页层无法强制旋转，竖屏提示保留。
3. **音乐与音效解耦**：此前 `audio.js` 只有**一个** `muted` 闸，BGM 与 sfx 共用 —— 关掉音乐会连带把按键音也关掉。现为两个独立闸（toggleMusic/musicEnabled、toggleSfx/sfxEnabled），UI 上是两个按钮（orb 栏 ♫/🔔，开始页 ♫ 音乐：开 / 🔔 音效：开）。

## 三、实测抓出并修掉的三处问题（数值检查看不出的）

| 问题 | 原因 |
|---|---|
| 顶栏被撑到 1020px 宽、右端 orb 组溢出 | flex 子项默认 min-width:auto，而顶栏是 nowrap —— 桌面大宽度把这个老问题掩盖了 |
| 发言流水被压扁、气泡文字裁切 | grid 单列的行高按内容分配，剩余高度不给舞台行 → 需显式 grid-template-rows: auto minmax(0,1fr) |
| 抽屉检查误报溢出 14px | 量到了 CSS transition 的中间态 → 需等 400ms 以上并校验 computed transform 为 none |

另有一条**门禁盲区**值得记住：原先只测「直接以横屏打开」，覆盖不到「竖屏打开后旋转」这条路径 —— 而旋转失败恰恰出在这条路径上，故另立 mobile-rotate-check.cjs。

## 四、备注 / 坑

- **cmd 调 build.cmd 必须用绝对路径**：在 PowerShell 里先 cd 项目再 cmd /c，会以工作区根为 CWD 解析，报「系统找不到指定的路径」（Set-Location 不改进程 CWD）；脚本内部用自身目录变量，不受影响。
- **APK 体积 1.4MB → 4.27MB**：主因是批 38 换入的 music-bgm.m4a（3.58MB，未压缩进包）。
- **XML 注释里不能出现双连字符**：manifest 注释里写 version-code 的双横线写法会让 aapt2 报 not well-formed (invalid token)。
- **aapt2 link 的版本号会被 manifest 覆盖**：AndroidManifest.xml 里显式写 android:versionCode / android:versionName 会**静默覆盖** build.cmd 传入的值（曾出现「日志打印 2.0preview、产物却是 1.0.0」）。manifest 已删除这两行，版本只由 package.json 经 build.cmd 注入。
- **速度档不持久化**：BGM 速度是模块级变量，刷新回到 ×1.00（未做 localStorage）。
- **竖屏提示层只在浏览器有意义**：App 已用 sensorLandscape 锁横屏，#rot-hint 在 App 内永不出现（网页层无法强制旋转，故保留）。
- 平板 / 折叠屏横屏后空间大，布局按单列 + 抽屉走，未做多列优化。
