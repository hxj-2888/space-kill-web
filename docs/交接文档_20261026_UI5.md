## 二、这一轮做了什么

### 2.1 ★ P0 · 待机帧全员不可见（先修，独立于本批主题）

**用户看到的**：对局页只有 15 个彩色椭圆 + 编号，**没有角色**（行走那 900ms 能看见）。

**根因**：`ui-scene.js` 给每个角色帧加的 `clipPath` 是 `<rect y="0" height="160">`，
而 `<g class="sk-frames">` 位于内层 `<svg viewBox="96 320 96 160">`。
`clipPath` 的坐标系是**引用者所在的用户空间** ⇒ 矩形被解释成 y∈[320,480]，
把待机行（image 的 y∈[0,160]）整块裁掉。行走时 viewBox 是 `0 0 96 160`（偏移 0），所以只有走路时正常。

**修法**：clip 矩形按**当前 viewBox 的原点**给，随 viewBox 一起换行。

```js
const vbParts = vb.split(' ');
const vbx = +vbParts[0], vby = +vbParts[1];
const clip = '<clipPath id="…"><rect x="' + vbx + '" y="' + vby + '" width="96" height="160"/></clipPath>';
```

> 不要改成 `clipPathUnits="userSpaceOnUse"`：那只是把默认值写出来，坐标系仍是引用者的用户空间。

## 三、改代码前必须知道的六件事

### 3.1 ★ 「元素存在」≠「像素可见」

P0 那个 clipPath 缺陷，614 条断言**一条都没拦住**：它们量元素在不在、id 对不对、包围盒相交与否。
Node 侧没有布局引擎，加不了"像素断言"。**结论：动场景/角色/纸片的改动，必须自己截图看。**

### 3.2 ★ 包围盒不是绘制范围（同一个坑，本批第二次踩）

`<svg class="sk-frame">` 的 `getBoundingClientRect()` 是 **124×258**，实际只画 **57×95**
（整张 384×800 行走图溢出到帧框外）。第一版书记官记录板用它判遮挡 ⇒ 报「压住 5~13 席」⇒
纸被挤到屏幕左上角。

**修法**：`SKScene.seatRects()` 读 `<g>` 的 transform + `svg.getScreenCTM()`，
按 `crewHtml` 里 sk-frame 的 x/y/w/h 逐项还原。渲染器与门禁**共用这一份**。

### 3.3 ★ `.add('hidden')` 是粘性的

`layoutClerk()` 最初在"取不到锚点"时 `add('hidden')`。切屏时 ResizeObserver 触发一次、
尺寸归零 ⇒ 加上 hidden ⇒ 回到对局后纸再也不出现。
**修法**：取不到锚点就 `return`，保留上一次位置。

### 3.4 ★ 纸张宽度受桌面限制，纸上不能放重复信息

`#stage-head` 里本来有「实时讨论 · 剩余 59s」，而纸下方已有「决策 59s」。
`.st` 定宽不缩 ⇒ 标题被挤成半个字。**纸上只留标题。**

### 3.5 ★ 上游的 `!important` 要用同样的 `!important` 抵消

`04-site-deepen.css` 的 `.cd-ring b{font-size:15px !important}` 会撑破 26px 的小环。
改上游会波及对局外所有环，故只在 `.clerk` 作用域内加同权重规则，并注释说明。

### 3.6 ★ 断言读错文件 = 红得有道理，但红在断言自己

`test-hudmap` 的 H11/H12 用"截取 HTML 片段"判控件归属，依赖
`</div>\n\n    <div class="board"` 这个分隔串。排版一变会误红（**红得可见，不会静默**），
但下一个人改 index.html 排版时要顺手看一眼这两条。
