## 一、口径闸门：`tools/seat-mode.cjs`（新增）

### 1.1 为什么要有这个文件

产品侧一直是对的：`js/main.js:36` 每次本地开局都掷席位变体，`Setup.rollSeatPicks` 用
**独立 RNG 流**（`state.js:141` 固定盐 `0x5EED5EED`），不消耗 `g.rng`。
错的是量测侧 —— 全部 `tools/*.cjs` 直接调 `Setup.createGame(seed,'random')`，从不传
`opts.seatPicks`。于是本地真实对局有 50% 概率出现猎手/窃听者/毒师/工匠/死囚外星人，
而**任何量测里这五个角色从未上过场**。

修法必须落在探针侧，不能动 `createGame` 的缺省值：`state.js:133-135` 的注释说明了原因 ——
独立 RNG 流正是为了保证「不传 `seatPicks` 的经典局逐字节同接入前」，改缺省会一次性漂掉
全部种子敏感断言与行为指纹。

### 1.2 三条纪律

| 纪律 | 做法 |
|---|---|
| 不改产品缺省 | 只改探针调用方式；`createGame` 与回归套件一字未动 |
| 口径显式 | `SK_MEASURE_SEATS=variants`（缺省）\| `classic`（历史对照）；非法值**抛错**，不静默回落；产品退路 `SK_SEAT_CLASSIC=1` 被尊重 |
| 口径进产物 | `meta.seatMode` + `meta.seatCensus`；`artifactFor()` 按口径给文件名（classic 沿用历史名，variants 加 `-variants` 后缀） |

同一模块顺带提供**种子分区**自检（`zoneReport`）—— 它与席位口径是同一件事的两条轴：
分区不可混算，口径也不可混算。

### 1.3 两种口径不是两套平衡

席位替换发生在 `rng.shuffle` **之前**且不改变数组长度，`rollSeatPicks` 又走独立 RNG 流
⇒ **变体局与经典局的 `g.rng` 消耗序列逐位相同**。所以两种口径可做严格 A/B：
观测到的差异只可能来自角色本身，不可能来自组局抽选或洗牌漂移。
（已用 `handsover-sim` 的 rng 中立性自证在两种口径下分别验证：均为 8/0。）

## 三、本批最重要的发现：**§4.3 的「警长巡逻矛盾」是探针自己的缺陷**

### 3.1 交接文档里的矛盾

```
步骤 2 的 req 条目总数      1130
其中 kind = patrol            0        ← 从不派发窗口
终局 patrolUsed = true       55/60 局  ← 却被用掉了
```

§4.3 判断为「`req` 与决策来源不一致的真实缺陷，交接后应优先查」。

### 3.2 实测结论：引擎是对的，探针读错了时点

直接包住 `Engine.STEPS['2'].req` 与 `.run` 观测（种子 241）：

```
步骤 2 run 结算：decisions[2]={"use":true,"targets":[2,3,7]}
   写前 patrolUsed=false → 写后=true   patrolCount 0 → 3
   patrolDmg 目标 = 2,3,7
```

引擎**确实派发了 patrol 窗口、AI 确实决策了、run 确实结算了**（3 人获得保护）。

### 3.3 根因：`g.step` 在 `stepOnce` 内部才被设成本次步

`engine.js:701` `beginStep` 才做 `g.step = step`，而 `beginStep` 是在 `stepOnce` 内部调的。
于是**任何钩在 `stepOnce` 外层读 `g.step` 的探针，读到的是上一步**：

```
钩在 stepOnce 外层看到的 g.step（=上一步）:
  null → 执行后 g.step=D-open
  D-open → 执行后 g.step=P-id
  ...
  1 → 执行后 g.step=2      ← 外层以为在跑步骤 1，其实引擎接下来跑步骤 2
```

后果：探针在步骤 2 结算**之后**才重算步骤 2 的 `req`，此时 `patrolUsed` 已被置真
⇒ `req` 的 `!p.patrolUsed` 条件不成立 ⇒ 恒不派发。**这正是「被用掉了却没有窗口」的成因。**

同源受害者（实测 120 局对照）：

| 声明面 | 外层口径（错） | 包 req 口径（对） |
|---|---|---|
| 触达声明面数 | 28 / 34 | **32 / 34** |
| `crew@0.6`（转职） | 0 次（假死面） | **有派发** |
| `sheriff@2`（巡逻） | 0 次（假死面） | **有派发** |
| `xeno@5`（双刀） | 0 次（假死面） | **有派发** |
| `listener@D-report` | 0 次（假死面） | **有派发** |

⇒ **§4.2「船员转职从未发生」与 §4.3「警长巡逻矛盾」两个结论都要改**：
转职窗口是**有**派发的，巡逻窗口是**有**派发的。此前 260 局里 `crew@0.6` 记 0 次、
`armed`/`tempdoc`/`assistant` 记 0 局上场，全部是观测缺陷。

### 3.3b 两个窗口的直接证据（`diag-transfer-window` 钩 req 后，200 局报数区）

```
步骤 2 派发 kind=patrol     = 107 次
步骤 0.6 派发 kind=transfer = 252 次
transfer 派发样本：
  {"id":4,"night":6,"role":"crew","alive":7}
  {"id":10,"night":6,"role":"crew","alive":7}
  {"id":6,"night":6,"role":"crew","alive":4}   ← 存活 4 ≤ 6，条件成立
  …
```

§4.2 说「两个条件一次都没成立（最长夜次 13、最低存活 2，可它们不在同一时刻）」——
**这个判据本身就是探针取错时点的产物**：真实派发 252 次，条件成立得很频繁。
§4.3 说「`kind=patrol` 恒 0 次」—— 真实派发 107 次。

⇒ 三个待办里的两个（§4.2 转职、§4.3 巡逻）**不是缺陷，是量测缺陷**。
`armed` / `tempdoc` / `assistant` 三个转职系角色**会正常上场**。

### 3.4 修法与新增自证

- `handsover-sim.cjs` / `classify-dead-surface.cjs`：按步**逐个包住 `req` 本身**，记引擎真实看到的派发；
  `classify-dead-surface` 的「该步是否被走到」改读 `g.queue[0]`（即将执行的步），不读 `g.step`。
- 新增**钩位自证**：`req` 被调用时若 `g.step !== step` 则计 `hookMisaligned++` 并非 0 退出。
  三区实测 0 —— 证明钩子装对了。
- req 纯净性自证的额外两次调用期间**关闭观测**（`OBSERVING` 开关），否则自证调用会被当成真实派发重复计数。

### 3.5 §七 的教训升级

原 §七.1 说「看到全 0 先怀疑钩子，再怀疑实现」。本批补一条更具体的：

> **钩子的位置决定读数的时点。** 同一个 `req` 函数，在 `stepOnce` 外层调与在引擎内部调，
> 拿到的是**不同时刻**的答案。凡是靠「读 `g.step` 再自己调 `req`」取数的探针，
> 都必须先证明 `g.step` 已经等于本次步 —— 否则整批读数错位一格，
> 而错位后的读数看起来「完全合理」（0 次、无异常），不会自己暴露。

## 四、变体口径暴露的 `req↔form` 分叉（**同源于已登记缺陷**）

变体口径下 `handsover-sim` 报出 req↔form 分叉（校准 12 / 验证 12 / 报数 12，上限截断），
三区形态**完全一致**：

```
步骤 8   reqKind=revive  formKind=doctor  convict=true  morph=<变形目标>
```

样例（报数区）：`role=engineer, morph=engineer, night=1`。

**这不是本批引入的缺陷**，而是 §6.1 已登记的 `IMPL_GAP['convict.revive.form']`
在变体口径下第一次被常规量测撞到 —— §6.1 末尾原本就写着「在变体接入量测之前，死囚根本
不上场，所以这个缺陷在任何常规量测里都不会暴露」。

补充一条**本批新查明的事实**：分叉只发生在**变形中**的死囚身上（`morph` 非空）。
死囚本体形态（非变形）在步骤 8 被派发 21 次，`req↔form` **零分叉** ——
因为 `form` 首行判 `isClassicXeno(p)` 读的是 `p.role === 'xeno'`（`actions.js:109`），
变形后 `p.role` 被改写成伪装目标（`steps.js:1943`），既不是 xeno 也不是 convict 的任何形态
⇒ 落到医生分支。

修法（给步骤 8 的 `form` 补 `revive` 分支）会改死囚行为，**需要点头**，本批未动。
