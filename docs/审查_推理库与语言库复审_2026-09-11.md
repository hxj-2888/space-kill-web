## 2. 🔴 新发现：NLP 否定极性缺陷（建议本批必修）

`parseClause` 里 `negated = NEG.test(cl)` 只用于**身份声称**（nlp.js:168）；查验汇报（chasha/facWord）、指控三档（accT）两条链**完全不看否定**，而 LEX.hard 的「是异形」是「不是异形」的子串：

### NLP-1（高）：否定式辩护 → 方向完全反转
```
输入：「3号不是异形，我信他」
输出：report = [{id:3, kind:'lock', faction:'alien'}]   ← 查杀（目标侧 B− 入账）
      accuse  = [3]（重度）                              ← onAccuse hard 入威胁度链
      defend  = []                                       ← 辩护分支永远到不了
```
实测复现（`NLP.parse` 直连）。后果：人类玩家在讨论里为队友作否定式辩护，会给全场 AI 写入「查杀 + 重度指控」双重假证据；`LEX.defend` 词表里的「不是异形/不是外星人/不是坏人」对**任何含编号的子句都是死词**（lock/accuse 在 defend 之前 return）。

### NLP-2（高）：「没有问题」→ 轻度指控
```
输入：「4号没有问题」
输出：accuse=[4]（轻度）          ← soft 词「有问题」是「没有问题」的子串
```
「没问题」（担保语义）与「没有问题」一字之差、方向相反，解析器不做否定极性检查。

### NLP-3（中）：正向辩护零识别
```
输入：「5号是好人」→ intents 仅「提及 5 号」，defend 空
```
`LEX.defend` 的「他是好人/是真船员」全带代词前提；「N号是好人/可信」这类最自然的背书句完全不被识别（defend 分支要求先命中 defend/defendT 词表才肯消费 ids）。

> **修复建议（一处收口）**：在 parseClause 顶部把「否定极性」解析为结构标记——
> `negEnemy = /(不是|非|没)[^。！？]{0,4}(异形|外星人|内鬼|坏人|狼)/` 命中时：
> ① chasha 强制 false、facWord 强制 'human'；② accT 降级或转 defend；
> 并把 soft 的「有问题」改为 `(?<!没)有问题` 或在 accT 判定前剥除「没/不是」前缀。
> 同步补 test-lang 用例：`不是异形 / 没有问题 / N号是好人` 三句的 round-trip。

## 5. 🟡 E7 承诺链：判据已修对，但「无米下锅」（新证据）

定向探针（60 局，挂 `Engine.submit` 空提交对齐 mc 驱动）：

```
登记承诺：{strong:3, mid:0, weak:3}   按 kind：{announce:3, vote:3}
结算记录：hit/miss/void 全部 0
```

- 唯一 strong 生产者 = decide.js:253（神探预告，kind='announce'）；weak 生产者（renderer「我可能会查验」）**无 targets** → settlePromises 的 `!(pr.targets||[]).length → continue`，永不结算
- announce 结算窗口 = 承诺夜+2 的投票回合，神探在此之前死亡率极高 → 多数走 void（100 局仅 2 次）
- **净效果**：E7 的 cred/miss 两表在真实对局中近乎恒空；A01 触发 19 次/100 局是唯一可见产出
- 附带确认：`promise` 的 **mid 档依旧零生产者**（昨日结论保持）

**建议**：要么给 promise 词表补 targets 抽取（weak「我可能会查 X」其实带编号），要么接受 E7 现状并在台账标注「展示性机制」。
