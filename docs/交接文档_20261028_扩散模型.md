## 三、★ 两个「不查源码找不到」的技术缺陷（本批最有价值的部分）

### 3.1 Z-Image-Turbo 出全黑图 → LayerNorm 在 fp16 下溢出

```
现象：512×512 出图是全黑（min=max=0，843 字节）
排查：权重干净（521 个参数 0 个 NaN）→ embedding 干净（std=2.19）
      → 但去噪后的 latents 是 65536 个 NaN
定位：给 transformer 每个叶子模块挂 forward hook，
      第一个产生 NaN 的是 `noise_refiner.0.attention_norm2`（一个 LayerNorm）
根因：fp16 指数范围只有 ±65504，LayerNorm 的平方和溢出成 inf，inf - inf = NaN
修法：**dtype=torch.bfloat16 贯穿全管线**
```

> ⚠ 只改 `quantization_config` 的 `compute_dtype` **不够**。
> 必须让 `prompt_embeds` 也是 bf16，否则报
> `mat1 and mat2 must have the same dtype, but got Half and BFloat16`。

### 3.2 SDXL 出纯黑图 → 原版 VAE 的 fp16 上溢

```
现象：换 SDXL 后同样是全黑
第一次修：把 VAE 用 fp32 加载 → 报
          `RuntimeError: Input type (struct c10::Half) and bias type (float) should be the same`
          （UNet 是 fp16、VAE 是 fp32，dtype 不一致）
正解：换 `sdxl-vae-fp16-fix`（专门为 fp16 重训过的 VAE），整条链保持 fp16
```

### 3.3 另外两个版本兼容问题

| 问题 | 报错 | 解法 |
|---|---|---|
| LoRA 需要 PEFT 后端 | `ValueError: PEFT backend is required for load_lora_weights()` | `pip install peft` |
| 新版 diffusers 挪了方法 | `AttributeError: 'StableDiffusionXLPipeline' object has no attribute 'enable_vae_slicing'` | 改成 `pipe.vae.enable_slicing()` |

## 四、★ 素材替换：四条路线全部失败（**这是本批的主要结论**）

### 4.1 四次尝试与失败原因

| 版本 | 做法 | 实测结果 | 失败原因 |
|---|---|---|---|
| **v1** | `pixel art, single object, game sprite` 提示词 | 一张 bed 里挤了 **7 件家具**（拼盘） | 「pixel art + game sprite」在训练数据里几乎全对应 spritesheet |
| **v2** | 产品摄影提示词 + 自己降采样 | 单件率高了，但抠底漏（椅子带花朵背景）、降采样成糊 | 照片 → 32px 的均值降采样会平均成中间色 |
| **v3** | 按目标宽高比生成（3:1 / 1:1） | **模型换了物体**：宽高比 3:1 的「桌子」画成空框、「椅子」画成柜子 | 换比例等于换了构图语义，模型改用「货架/桌子腿」的模板 |
| **v4** | 以现有精灵为骨架 img2img（strength 0.42） | 轮廓保住了，但**只加噪点、没加细节** | 32~64px 尺度上没有细节可补 |

### 4.2 定量证据：新图比原图更「糊」

「糊」不是主观判断，下面两个量能说明：颜色数（越多越脏）与相邻像素差（越小越平）。

```
            原图                      新图（img2img）
bed      7 色 / 相邻差 16.05    →   20 色 / 11.76
desk     7 色 / 18.36           →   20 色 / 16.09
chair    4 色 / 17.73           →   16 色 / 12.64
console 11 色 / 31.28           →   20 色 / 25.53
```

**颜色数翻 3~5 倍，局部对比度反而下降** —— 这正是「糊」的定量定义。
像素风的锐度来自**少色 + 高局部对比**，而扩散模型给的恰好是反向：多色 + 低对比的过渡带。

### 4.3 根因：让模型「做设计」而不是「补质感」

让 SDXL 从零画一件**正好落在 32px 网格上的游戏家具**，等于要求它做工业设计；
而它擅长的是给**已有的大图**补质感。在 32~64px 这个尺度上，它没有可用的细节可补，只能加噪。

> 这条与 AGENTS 红线 9「元素存在 ≠ 像素可见」是同一族教训的延伸：
> **「生成出来」≠「能用」**。断言、截图都只能证明「有图」，证明不了「图更好」。

### 4.4 顺带否掉的两条捷径

- **用 `--only` 挑好图**：同一 prompt 换 seed 仍会在「拼盘 / 换物体 / 加噪」之间跳，不是 seed 问题。
- **加大 LoRA 权重**：从 0.55 拉到 1.3，只会让「拼盘」的格子更像素化，不能让它变成单件。

## 六、性能实测（决定「能不能当管线用」）

| 模型 | 配置 | 单张 512×512 | 备注 |
|---|---|---|---|
| Z-Image-Turbo | Q8_0 GGUF + bf16 | **290 s** | 8GB 显存全满，绝大部分时间在换页 |
| Z-Image-Turbo | Q4_K_M GGUF | 未测出图 | 只验证了加载 |
| SDXL + pixel LoRA | fp16 + vae-fp16-fix | **42 s**（8 步） | 12 步约 70~80s |
| SDXL 纯文生图（房间概念） | fp16 | 70~80 s | 输出像「产品图」不是「俯视房间」 |

> Z-Image 慢的原因是 GGUF 反量化在 8GB 卡上要做显存换页 —— 显存剩 0GB 时每步都在搬。
> **SDXL 快 7 倍且像素风原生**，本机应以 SDXL 为主。

## 八、下一批的三个方向（用户尚未选定）

画面模糊的**真实原因**（第一轮就量出来了，不是"素材画得不好"）：

```
TILE = 56，源家具 32px/格  ⇒  1.75 倍上采样（非整数，最糊）
若源改 64px/格            ⇒  0.875 倍下采样（更锐）
```

| 方向 | 内容 | 工作量 | 收益 |
|---|---|---|---|
| **A** | 把 22 件家具**程序化重绘到 64px/格**，沿用 `gen-crew-sprites.cjs` 的写法（加一档明暗 + 1px 描边） | 大 | 高且可控 |
| **B** | 扩散模型**只做单件大图**（5 件交互道具、图鉴插画、主页背景） | 中 | 中，但已验证可行 |
| **C** | 只修渲染倍率：TILE 56 → 64（或 32），让上采样变成整数 2 倍 | 小 | 立竿见影，但不增加细节 |

**推荐 A + C 一起做**：先让倍率变成整数消掉插值糊，再用程序化方式提分辨率。
纯扩散路线（D）已被 §四 证伪，不要再试。
