## 二、根因：这不是审美问题，是比例问题

上一批（UI-5）删了 HUD、把房间画全了，但布局仍浪费严重（1600×900 实测）：

```
主区 #scene-mount   1568 × 581        比例 2.70
房间 26 × 17 格     比例 1.53
```

场景 SVG 用 `meet` 等比缩放 ⇒ 房间按**高度**绑定 ⇒ 只能占 1568×0.56 = 876px 宽，
两侧各空 346px。**改 CSS 没用**：任何居中 + meet 的组合都会得到同样的结果。

唯一出路是让房间的宽高比接近主区。`30 / 11 = 2.727`，与 2.70 相差 1%。

### 3.1 行动面板：为什么是"贴底抽屉 + 两档形态"

```
桌面档（视口高 > 560px）
  面板 absolute 贴底，不占流内高度 ⇒ 场景恒 789px（改前有面板时 543px）
  它会盖住房间下沿那排（1/2/15 号）⇒ 座圈**纵向压扁**（锚定上沿，×0.55）让位
  压扁而不是平移：平移受房间上沿限制（最多 84px），实测需要 98px，抬不动

矮横屏（视口高 ≤ 560px）
  场景 824×356，座圈就占 227px，面板还要 226px ⇒ **几何上不可能共存**
  ⇒ 面板走**模态抽屉**：盖住场景、场景压暗、高度 62vh
     此刻玩家要做的就是在面板里点目标，场景不是必要信息
```

> ⚠ 不要试图在矮屏里"让座圈躲开面板"。实测把座圈压到房间上沿，仍会压住
> 1/2/3/4/13/14/15 **七个**席位。那是几何不可能，不是参数没调好。

## 五、★ 这一批几乎全踩在「门禁没在测东西」上

### 5.1 我写的门禁空转了两次，反向自检才抓出来

给「面板浮出 ⇒ 座位让位」加了 `SEAT_LIFT` 之后写了一条门禁，然后做反向自检：

- 把 `SEAT_LIFT` 改成 `0` → **没变红**
- 把座位抬升整行注释掉 → **还是没变红**

原因：探针只往 `#stage-actions` 注了一个按钮 ⇒ 面板只有 **82px** 高 ⇒ 永远压不到人。
真实决策表单是「公告 + 说明 + 15 个头像目标 + 提交行」，实测 **320px**。

> **一条从不失败的断言，比没有断言更危险** —— 它让人以为这里有防护。

修法两条：
1. 探针按 `renderForm` 的真实结构灌 15 个 `tgt-avatar` + 一个 `<select>`
   （`hasActions` 的判据是 `#stage-actions` 里有**非提交控件**，只注按钮不成立）；
2. 加**探针自检**：面板高度 < 140px 直接判红（"探针没复现真实表单高度，断言会空转"）。

### 5.2 写死参数的"让位"是假的

| 版本 | 做法 | 实测结果 |
|---|---|---|
| v1 | `SEAT_LIFT = 1.2` 格 | 桌面档差 16px 照样压住 |
| v2 | 按实际重叠算抬升量 | 桌面档过了，矮屏仍压 3 席 |
| v3 | 抬升上限按房间可用高度算 | **更糟**：矮屏压住 7 席 |
| v4 | 桌面压扁 + 矮屏模态 | 两档都过 |

v3 之所以更糟：矮屏房间只有 356px 高，座圈本身就 227px，"按可用高度算上限"把上限算成了 0。

### 5.3 压扁只改了角色，没改座圈

`squashSeatY` 第一版只用在角色 `py` 上，画座位椭圆的循环还在用原始 `s.y`。
截图一眼可见：**黄色 3/4 号只剩空圈，角色飘在别处**。
修法：两处都走 `squashSeatY` —— 一处定义、两处消费。

### 5.4 画布等于房间 ⇒ 边缘的门被裁一半

门锚点就在房间边界上（`side='l'` 的 x=0），以锚点为中心画 0.7×2 格 ⇒ 一半在画布外。
实测左右门标签显示成「查室」「制药室」。
修法：按 side 把矩形**收进边界内侧**，标签也跟着进。

### 5.5 旧断言的判据会随设计一起过期

| 断言 | 旧判据 | 为什么过期 | 新判据 |
|---|---|---|---|
| `主区L` | 矮屏面板压到 10vh | 那是**面板挤压场景**时代的口径；面板改成浮层后 10vh 把表单缩成 39px，15 个目标点不到 | 矮屏走模态抽屉（≥62vh）+ 场景压暗 + 禁止 10vh |
| `主区K` | `#region-dec` 必须 `position:relative` | 那条救过真实的"面板压住 1/2/15 号"，不能简单放开 | 面板若 absolute，`setPanelOpen` 联动必须齐备 |
| `UI3a-d` | 面板/输入都在流内 | 同上 | 输入仍须在流内；面板则要求联动齐备 |

三条都保留了**行为层实测**（mobile-layout-check 四档视口），结构断言只守"联动存在"。

### 5.6 删掉 clipPath：它在**某些房间**里把角色整块裁掉

走查宿舍时 15 个席位只剩彩色圈、角色全不见 —— 与 UI-5a 修的 P0 同一症状，但**舰桥是正常的**。
运行时去掉 `.sk-frames` 的 `clip-path`，两个房间都恢复。

结论：`clipPath` 既**多余**又**有害**：
- 多余：嵌套 `<svg>` + CSS `.sk-frame { contain: paint }` 本来就裁到帧框内
  （去掉后每帧仍只出一格，没有"整张行走图铺开"）；
- 有害：`clipPath` 的用户空间在"外层 svg / 内层 svg"之间有歧义，
  **同一份代码在不同位置表现不同** —— 这解释了那个 P0 为什么修了还会复发。

> UI-5a 当时把 rect 改成跟着 viewBox 原点走，把症状从"所有房间看不见"压成
> "部分房间看不见"。**治好症状不等于找到病因。**

修法：删 `<clipPath>` 与 `<defs>`，只留 `overflow="hidden"` + `contain: paint`。

### 5.7 装饰地毯不能画成实心

宿舍右侧一大块实心深色，读作「地上挖了个洞」，比空着还难看。
分两种画法：舰桥那张（`anchor='clerk'`，玩家眼里的"大桌子"）实心；
其他房间的装饰地毯只画**虚线轮廓**。
这个教训主页付过一次（批 H1），当时只改了主页那处。

### 5.8 背景压太黑 = 另一种"黑区"

房间改成满宽后上下各留约 107px 边条。背景图原来压到 `brightness(.30)`，
那两条几乎纯黑 —— 正是用户反复说的"黑区"。
提到 `.52` 后读作"船体外壳"而不是"没渲染"。
