## 二、为什么需要这一层（实测依据，非推测）

B0 后侦察（`docs/v7_B0后对局侦察报告_20261008.md`）留下两条硬事实：

1. **角色差异化在退化**——各角色「见到的证据家族数」普降且趋同（detective 5.0→3.5、crew 5.5→4.0，仅 inspector 变宽）。
2. **发言层高度同质**——句子多样性仅 11.8~12.6%，最高频单句被重复 800~900 次。

根因很具体：`decide.speak` 的取材与模板池**按 faction 而非按角色**分支——
9 个人类角色共用同一批 `pick(rng, [...])` 句子。所以「让它们有各自的想法和发言」不是加几句新台词，
而是**让每个角色按自己卡上的情报面开口**。速查卡正好给了这个依据：`duty.senses`（可见性列即白名单）
与 `duty.cost`（明文代价）。

## 三、设计

### 3.1 两个组成部分

**「想法」= `AIVoice.thought(g, p)`**
按 `duty.senses` 的**声明顺序**逐个取料，第一个有料的即为主导话题。每个键一个「话题」= `probe`（取料）+ `line`（成句）。
取不到料就返回 `null`，**不制造噪声**。明文代价（`duty.cost`）以犹豫小句的形式挂在后面——
神探怕暴露、毒师怕误伤、验票官怕发动会议即报编号、嗅探看不到全额减免……这是「有想法」的另一半。

**「发言」= 在 `decide.speak` 已成文的发言前**前置**一句**
分支链照旧跑完，指控、质询、应答、战术/情绪语料该产出什么就产出什么；voice 只**加**一句在前面。

### 3.2 为什么必须「前置」而不是「后置」

拟人Ⅳ 的检查点按「发言以情绪句结尾」判定（`tx === x || tx.endsWith(x)`）。情绪句来自 `Tactics`/`SAFE` 分支，
**后置会把它挤到句中而使该断言变红**（v1 已实测变红）。前置则情绪句仍在句尾。
中文口语上前置也自然：「我嗅过 4 号身上有保护——不过 5 号今晚死得蹊跷。」先摆料，再接话。

### 3.3 关键约束与它们的处置

| 约束 | 处置 |
|---|---|
| 不得吞掉指控义务 | voice 完全不参与分支选择，指控分支逐字未动 |
| 异形对其他阵营不公开队友（卡·可见性） | 队友类话题 `claim = null`，且话术**可否认**（只给体感不给证据，不报编号） |
| 非人类已有卡内专属语料层（拟人层 N349~N386、N351 情绪句） | voice **只对人类阵营**取地板，避免顶掉 `Tactics` 分支（顶掉会让拟人Ⅳ 断言变红） |
| 声明层是唯一真源 | 按 `DUTY_SENSE` 的键组织话题；`auditTopics()` 强制「声明了的每个情报面都必须有话题实现」 |
| D6 纪律：族判定必须走能力标签 | `ownAmmo`/`armedCrewIds` 走 `grant 'shoot'`，`dyingList` 走 `grant 'save'` |
| 已被既有分支覆盖的话题 | `selfClaimLog`（crew 分支）、`checkPool`（detective 分支）标 `defer` 让位——顶掉它们会**丢 lock 宣称** |

### 3.4 三次迭代与各自代价（同一批评测口径，种子 1–200）

| 版本 | 做法 | 指控条目 | 证据条数 | 句子多样性 |
|---|---|---|---|---|
| 基线 | 无 voice | 1848 | 269268 | 12.4% |
| **v1 替换式** | 作为分支链第 2 位，顶掉指控/质询 | 1384（**−25.1%**） | 214680（**−20.3%**） | 14.2% |
| **v3 纯附加式**（本批） | 链末前置，不参与分支选择 | 1772（−4.1%） | 273343（**+1.5%**） | **20.9%** |

v1 的问题很明确：多样性确实变好，但**指控被削**，而指控是投票与推理链的输入——这已越出
「让角色有各自的想法和发言」的授权范围。证据 −20.3% 的构成是 `speech(公开发言) −30829`、
`ans（应答）−17566`，两者都是指控分支的下游产物，正好印证这一点。改为纯附加后两项归位。

### 指控为什么还掉了 1.8%——不是分支顶替

`git diff --numstat js/ai/decide.js` = **`43  0`**，即**零删除行**，没有任何既有分支被改动或抑制。
残余的 −1.8% 来自 `g.rng` 是**游戏级共享随机流**：voice 取随机必然让整条流移位，
下游（其他玩家的取样、当晚行动、投票）跟着变。**措辞要说准：「分支选择不变」成立，
「整局逐步一致」不成立**——后者只能靠上表实测说明，不能靠注释断言。
对比 v1 替换式的 −25.1%，纯附加式把这一项收窄到了噪声量级。

## 六、诚实登记（未做 / 有意不做 / 待补）

1. **平衡不作宣称，也未回填**。报数区 −4.6pp 与校准/验证区 +2.5pp 方向相反，两者都未达 2σ。
   两个独立证据未同向 ⇒ 结论只能是「与噪声一致」。不为凑数字调参。
2. **`dyingList` 显式登记为「卡载但本层无消费者」**（`notApplicable`，须写 `reason` 否则 `auditTopics` 拦）。
   原因：濒死只存在于夜间（置真 `steps.js:273/288`、`engine.js:148`；救援或死亡后清
   `steps.js:1365/1404/1418/1475`），而发言在白天讨论会——那时濒死者要么已被救、要么已出局。
   **不是引擎缺载体**（`p.dying` 夜间有效），是信息窗与消费窗不重叠。
   实测 `probeAll` 探测 744 次、有素材 0 次。要有用需把濒死名单做跨夜留存（像 `markEverSeen` 那样），
   那是引擎补充项，超出本批授权，**列为待办而非硬凑实现**。
3. **`attackTypeOnGuard` 属遮挡，不是缺陷**。它与 `guardFeedback` 读同一条 `priv` 文本，
   前者在 `duty.senses` 里排后面，被先命中的遮住。实测探测 678 次、**有素材 88 次** ⇒ 载体是活的。
4. **「零命中」必须拆成三种性质**，否则真缺陷会被当成排序问题放过：
   `shadowedByEarlierTopic`（素材在，排序问题）/ `noMaterialInThisLayer`（本层取不到料，需查载体或时间窗）/
   `neverProbed`。为此新增 `AIVoice.probeAll()`（不按 `thought` 的顺序短路），
   探针按此三分类输出。本批正是靠它把 `dyingList` 判成真缺口、把 `attackTypeOnGuard` 判成遮挡。
5. **B0 遗留的载体薄弱**：卡载的「仅本人可见」那几类（受袭感知 / 协助维修人数 / 致死来源清单 / 嗅探结果）
   在引擎里**只剩 `priv()` 文本一条落点**（`p.inbox`）——B0 归档了 `MoE.absorbPrivate`，`own:*` 归零。
   本批的 voice 只能从 `p.inbox` 取料。四条正则已与引擎原文**逐字比对通过**
   （`本夜共有 N 名普通船员协助维修` / `N 号落身致死来源：` / `受袭感知：…伤害类型为「X」` / `p.sniffLog`）。
   但正解是 B1 把它们收进 `Vision.record()` 的结构化落点，而不是长期靠解析 inbox 文本。**列为待办。**
6. **仍未做**（承接上一批队列）：B3（决策读材料，风险最高，须独立 PR + 同种子 A/B）、
   B5（删分数残留 + DEV 面板迁到新引擎监控按钮）、B6（`convert` 不可达 / `craft` 席位 / 12 条死战术条目），
   以及待你裁定的四项：自我治疗额度口径、v4 6.2 反停滞是否迁到 4b、
   船员协助维修是否拆成独立 4a、异形 3% 破坏率（`decide.js` 里 `uDestroy` 从未压过 `uAct`）。

## 七、本批自身修掉的真实缺陷（留着当记录）

1. **8 个话题的取材字段引擎从未写入**（`_guardedNight` / `_guardHitType` / `_repairN` / `_savedCause` /
   `_sniff` / `lastSniff` / `lurkResult` / `_lastLurkTarget`，引擎侧命中数全为 0）——
   导致 bodyguard **永远无话题可讲**。真实载体是 `p.inbox`（`priv` 文本）、`p.sniffLog`（`steps.js:552`）、
   `p.lastXenoCheckRes`（`steps.js:407`）。改正后 bodyguard 从「—」变成 `guardFeedback ×141`。
2. **违反 D6 纪律**：曾用手写角色族判定链（`[hunter,armed]` / `[sheriff,armed]` / `[rescue,tempdoc]`），
   被 `test-fix-v26` 的 D6 lint 拦下（该 lint 要求族判定链为**零**）。改走能力标签 `shoot` / `save`。
3. **情绪句回归**：voice 分支插在链首，把**非人类阵营**的 `Tactics`/`N351` 情绪句分支整条顶掉，
   拟人Ⅳ 的「情绪句命中」断言归零。处置：voice 限定人类阵营；非人类保留其卡内专属语料层。
4. **探针把转职船员记错**：角色标签用 `originRole`，导致转职为武装的船员被记到 `crew` 头上
   （读数上「crew 的首要话题是 `ownAmmo」——船员哪来的子弹）。改用 `p.role`（当前身份，
   转职后 AI 应以当前身份说话）。
5. **`tools/load-order.cjs` 被插入脚本写坏**（两处）：`AI_STACK` 被拼进 `ORDER` 的内容；
   声明行里混进一个字面 `\n`；且 `ORDER` 段漏了 `ai/voice` 导致 `full` 剖面加载不到 `AIVoice`。
6. **我的补丁脚本误删既有代码**：按 `}` 定位链末时匹配到了更靠后的闭合括号，把
   `v26 claims` 记录块与私聊交底块一并切掉。处置：`git checkout js/ai/decide.js` 回到 HEAD，
   改用**行号定位**（CJK 锚点在脚本里会被改写，已连续踩到）重新一次性接入。
7. **行尾混用造成真实事故**：往 CRLF 的 `index.html` 插入 LF 换行，使 voice 与 decide 两个
   script 标签落在同一个 `\r\n` 分隔单元内；随后「只修那一行乱码」的操作替换了整单元，
   **连带删掉 `decide.js` 的 script 标签**——加载链断裂后浏览器端整片 AI 静默失效。
   处置：从 HEAD 还原 + 用文件自身行尾重插 + 加 6 项加载链校验
   （voice/decide 均在、voice 在前、无裸 LF、标签数未减）。教训写进了脚本注释。
8. **`js/ai/voice.js` 自身**：2 个 CJK 字符被写成 U+FFFD 乱码、且行尾是 LF 而 `js/ai/` 其余为 CRLF。
   已修字符并统一为 CRLF（混用行尾正是第 7 条事故的成因）。
