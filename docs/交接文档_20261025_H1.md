**旧结构**（四层叠加同一个卡片）：

**新结构**（无卡片，整屏舞台）：
```
#screen-start
  ├─ .start-top        标题 / 状态 chip / DEV / ⚙ 设置
  ├─ .preview-note     可展开的小铭牌（默认只显示一句）
  ├─ .arena-nav.left   身份图鉴 · 规则速览 · 对局回放

  ├─ #seat-tag         「我这席」名字牌（贴在自己座位上，点它改身份+改名字）
  ├─ .arena-nav.right  随机 · 指定阵营 · 联机
  ├─ .arena-foot       ◉ 开始对局（整页唯一呼吸动效）
  └─ [hidden] 隐藏宿主：faction-pick / role-pick / seed / online-card / start-actions / bgm
```

**关键**：所有旧控件的 `id/name/value/disabled` **一个没动**，只是加了 `hidden` 属性、
并由新铭牌去写回它们。这是 `S4D` 与 `mobile-layout-check` 能继续绿的原因。

## 三、改代码前必须知道的五件事

### 3.1 ★ 级联顺序：09 必须最末，且要提特异性

`03-dual-page.css` / `05-late-overrides.css` / `07-start-scene.css` 里有一大批
`#screen-start .start-box > *{position:relative;z-index:1}`、`#screen-start .panel-grid{flex:1 1 auto}`
这类规则。它们会把新加的铭牌**压成流内 flex 项**——第一版实测：左侧铭牌跑到左上角、
右侧铭牌 `x=-26`（跑到屏幕外）。

修法：`09-arena.css` 里用 `#screen-start .start-box > .arena-nav`（更高特异性）+
`position: absolute !important`。**不要只靠级联顺序**。

### 3.2 ★ `[hidden]` 压不住旧宿主

`03/04` 层有 `#screen-start .faction-pick{display:grid}` 这类规则，
`display:grid` 会覆盖 `[hidden]` 的 `display:none`。结果四个阵营 label（带 DiceBear 头像）
以"一堆小人"的样子被渲染到页面上。

修法：`09-arena.css` 末尾一段 `#screen-start [hidden]{display:none !important}`。

### 3.3 ★ 嵌套 `<svg>` 的裁剪不可靠

主页要画「我这席」的小人，素材是 **4 列 × 5 行**的行走图（单帧 96×160）。
用嵌套 `<svg viewBox="96 160 ...">` 只框一帧 —— 实测**不裁剪**，
整张 4×5 图被完整画出来，画面上就是"一堆红小人"。

修法：用 `<clipPath>` 框住窗口，再把整张图平移到位（`renderHomeScene` 里那段）。
**别用嵌套 svg 做 sprite 裁剪。**

### 3.4 ★ 座位圈必须比桌子大

`js/space.js` 里舰桥原来是 `seats:{cx:11,cy:7,rx:5.2,ry:3.2}`，而桌子是 `x:9,y:6,w:4,h:2`
（半宽 2、半高 1）。`rx=5.2` 看着比 2 大，但座位是**椭圆参数角均分**，
短轴方向只有 3.2 格 —— 15 席实际压在桌面上。

修法：房间 22×14 → 26×17，座位圈 7×4。**改完必须跑 `node tools/test-space.cjs` 的 U1C**
（它算道具越界与重叠）。

### 3.5 ★ 对局回放不得直读 `g.replay`

红线 K3 lint 按行扫 `g.replay`。回放内容只能经 `View.replayOf(g)` 发放。
`arena.js` 第一版写的是 `g.replay.length` → K3 直接红。改法是取 `View.replayOf(game)`
（同时把局部变量改名成 `game`，否则 lint 仍会命中）。
