## 一、本批起因：玩家报出的三个现象，实测指向同一个根因

玩家（以死囚席位试玩）报了三条：

1. 「死囚外星人不具有经典外星人的所有技能，这里存在耦合」
2. 「死囚没有发动变形，怎么能够直接切换身份呢？」
3. 「我明明作为神探，却还可以发动医生的技能」

结论先写：**三条是同一个根因的三个切面**，不是三个独立缺陷。

### 根因：把「阵营成员」当成了「能力持有者」

死囚外星人全程 `p.faction === 'xeno'` —— 这是**对的**，6.8.2 明文它是外星人阵营成员，
参与清场与胜负判定，`engine.js` 的胜负统计必须继续按 faction 判。

但经典外星人的全部技能（蛰伏查验、蛰伏沉默、双刀、破坏、夜晚免疫、感染治疗额度、乔装）
在代码里**也都按 `faction === 'xeno'` 派发**。于是：

- **未变形的死囚**（`role === 'convict'`）照样拿到蛰伏／沉默／击杀／自我治疗 → 现象①
- **变形后的死囚**（`role === <所变形身份>`，`faction` 仍是 `'xeno'`）同时拿到
  所变形身份的技能**和**全套经典外星人技能 → 现象①的加强版

### 现象③ 的机制：req 与 form 的 kind 不一致，静默换了一套技能出来

这是最隐蔽、也最值得记住的一段。步骤 8 的派发与表单用了两个不同的判据：

```js
// steps.js 步骤 8 · req —— 按 faction
if (p.faction === 'xeno' && !p.branch && p.infection && ... && p.cureSelf > 0)
  out.push({ pid: p.id, kind: 'xenoCure' });

// steps.js 步骤 8 · form —— 按 !convict
if (p.faction === 'xeno' && !p.convict) { /* 自我治疗表单 */ }
// ……else 落到医生表单分支
```

死囚被派发了 `kind='xenoCure'`，但 `form` 的分派条件里 `!p.convict` 为假，
于是**继续往下走，落到医生表单分支**。玩家提交的是「治疗/救援/制药/毒药」，
引擎拿到的 `d` 却按医生语义解读。

**死囚变形成神探后，这段代码原封不动地跑了一遍：玩家看到「医生的技能」。**
这就是现象③，也是它此前能一路穿过 550 条断言的原因 —— 断言跑在 Node 里，
从不构造真人表单，也从不比对 `req.kind` 与 `form.kind`。

### 现象② 的机制：变形后拿到了普通船员的转职

变形会把 `p.role` 改写成 `'crew'`。而 0.6 转职的派发条件是
`RD.hasGrant(p.role, 'transfer')` —— `crew` 的 grants 里正有 `transfer`，于是门禁自动放行。
6.8.3⑦ 明文「变形者不得转职」，代码里没有任何对应判据。

## 二、修法：一个判据，而不是到处打补丁

新增推导层三判据（`js/v66/derivation/actions.js`）：

| 判据 | 含义 | 用在哪里 |
|---|---|---|
| `isClassicXeno(p)` | 经典外星人**技能**持有者＝`role === 'xeno'` | 技能派发与结算 |
| `isXenoCamp(p)` | 外星人**阵营成员**＝`faction === 'xeno'` | 胜负、清场、感染免疫、阵营面板 |
| `isMorphed(p)` | 变形者（含未变形的死囚本体） | 禁止转职 |

关键在于：把技能判据从 faction 换成 role 之后，**死囚的两种状态都自动落空** ——
本体形态 `role === 'convict'`、变形后 `role === <所变形身份>`，两者都不等于 `'xeno'`。
不必在每个派发点写 `!p.convict`，也不必担心「变形成某个身份后又漏一次」。

> 分层的意义：这是推导层加一个判据，执行层换一处调用。加新变体职业时，
> 「它持不持经典外星人技能」这个问题由 role 键唯一决定，不需要新增任何分支。

6.8.3⑧ 变形为异形时「克隆其**除社交与队内共享外**的一切能力」，故变形者不得队内私聊。

## 三、顺带修掉的两个隐藏缺陷

### 1. 镜像账本缺本体槽（2.8.5③ 形同虚设）

`state.js` 原本执行 `M.enter(p.mirror, 'convict', 0)` 意在「本体形态自开局在位」。
但 `morphPool` 只给**可变形身份**（池内不含 `convict` —— 不能变形成自己，正确），
`build` 因此从未建出 `convict` 槽，`enter` 对不存在的槽**静默返回 false**。后果：

- `activeKey()` 恒为 `null`，本体形态从未登记为「当前在位」
- 变形时 `M.has(mirror, p.morph || 'convict')` 恒假 ⇒ 离开本体形态时状态无处封存，
  切回时也无状态可恢复

修法：在建池时显式追加本体槽 —— 它不是变形目标，只是「当前形态」的记账位置。

### 2. 变形为异形的死囚选了破坏，什么都不会发生

4b 的 req 原本按 `faction` 分派，变形为异形的死囚 `faction` 仍是 `'xeno'`：
走进外星人分支、而 `destroyLeft` 恒为 0 ⇒ 破坏**整个落空**（选了没反应）。
两侧都改成按 role 判后才拿得到异形破坏分支。6.8.6② 的注释本就写明
「死囚呈现异形时破坏，按字面身份为异形，故不触发停转夜」—— 代码比注释落后了一步。

## 四、面板侧（这是玩家真正看见的那一层）

`selfPanel` 此前按 faction 罗列资产，于是死囚的阵营页上并排显示着
**夜晚免疫／双刀／破坏／感染治疗额度**四条它一条都用不了的技能，
而它真正持有的**变形与复生一条都不显示**。变形后更荒唐：外星人资产与所变形身份的资产同时出现。

现改为按 role 判，并补上死囚自有的三行：当前形态、复生额度、镜像账本（各可变形身份一览）。

## 五、新增门禁（567 条断言 + 冒烟）

### `tools/test-fix-v26.cjs` §43 组（17 条，死囚A~Q）

关键的一条是 **43.6 通用探测器**：

> 遍历每个步位的 `req` 派发的 kind，断言与 `form` 返回的 kind **逐次一致**。

现象③ 正是这类不一致造成的。这一致性此前**没有任何断言覆盖**，因为断言跑在 Node 里、
从不构造真人表单。现在它在经典局与死囚局两套构成下逐夜比对（实测覆盖 200+ 次派发）。

**每条门禁都做过「回退验证」**，确认非空跑：
- 回退 43P 所依赖的派发门禁 → 43P 失败（`实得=xenoCure`）
- 回退被动发放门禁 → 43H 失败（`cureSelf=1`）
- 回退 `ui.js` 的面板门禁 → 冒烟报 6 处异常

### 门禁分层上的一个坑（值得记下）

43.2 的两处门禁（被动发放 / 步骤 8 派发）**互为冗余**：任一处单独失效，另一处仍能挡住症状。
所以「回退任意一处」都不会让 43E/43H 报警 —— 那是纵深防御，不是断言失效。

要真正验证**派发侧**的门禁，必须让死囚手上真的有额度，否则条件短路、断言变成空跑。
故补了 43P（构造「已感染且持有额度」的满配死囚，直接断言步骤 8 不派发 `xenoCure`）
与 43Q（同条件的经典外星人**仍应**被派发，确认门禁没把能力误关）。

## 六、顺带修掉的测试基础设施缺陷

### `tools/uismoke.cjs`

1. **标签页切换从未被覆盖过** —— DOM 桩的 `querySelectorAll` 恒返回 `[]`，
   而 `ui.js` 的标签页 onclick 正是靠 `#nb-tabs .tab` 绑定的。于是阵营页
   （`selfPanel` 唯一的渲染入口）在自动化里**从未执行过一次**。
   现从 `index.html` 解析真实 `data-tab`（避免与页面结构漂移），并补跑 `UI.init()`。
2. **失败不落退出码** —— 断言命中时脚本仍以 `0` 退出，`npm run test:all` 一路绿灯。
   已补 `process.exitCode = errs ? 1 : 0`。
3. **定时器桩**：`setTimeout` 改为不触发。若在桩里同步执行会引入真实环境不会有的重入
   （实测曾导致 `renderForm` 读到半初始化状态）。

新增的阵营页断言比对的是**整行标签**而非子串：「感染治疗额度」含「治疗额度」，
用 `indexOf` 判定会把「外星人行漏进来了」判成通过。
