## 〇、两条纪律，写在最前面

> 「裁判探针可以有上帝视角，模拟 AI 探针不可以；这是纪律。」

首版 `tools/human-ai-parity.cjs` 违反了它 —— 那一个文件同时是裁判和模拟器，
于是在跑对局的过程中读 `p.faction` 判队友、读 `originRole` 判变形身份。
**上帝视角混进了模拟路径。**

本批拆成两个文件，边界不可越：

| | 模拟臂 `parity-sim.cjs` | 裁判臂 `parity-referee.cjs` |
|---|---|---|
| 跑对局 | **是** | 否 |
| 读真相字段 | **否**（一个字都不许出现） | **是**（它就是裁判） |
| 改对局状态 | 只读不写 | 不碰对局 |
| 产出 | 账本（决策 + 「读了哪个字段」） | 判定（违例清单） |

模拟臂的读取记录装置**只 push 一个字符串到账本**，不读值、不判对错、不返回任何东西。
裁判臂自己按同种子重放取状态（对局确定性 ⇒ 重放逐位相同），**不装任何记录器** ——
裁判若装了记录器，就等于裁判改了对局。

自证：模拟臂末尾跑「装记录器 vs 裸跑」两遍比对指纹。60 局实测 **8/0**，
证明记录器只看着、没碰着。

首版那个文件已删除（它的判据与结论已并入新两臂）。

## 二、裁判臂判定：三维度

### ① 动作空间 —— 完全对等

15937 条决策 **100% 有表单可对照**；AI 交了表单外的

### ② 信息边界 —— **三处真实越界**（首版只报出一处）

去重读取对 61167 个。分档：
`VIEW` 23845 / `OWN_FORM` 24985 / `DERIVABLE` 3929 / `TEAMMATE` 144 / `DECLARED_SENSE` 344。

#### 越界① `silenceNight`（全体，共 5615 次）

`js/ai/belief.js:108`（`actF` 活跃度函数）无条件读 `p.silenceNight`。
三条依据：速查卡 `silence` 出现 **0 次**；`view.js` 他人分支不下发它；
`steps.js:460/461` 只 `priv` 给本人 + `god` 给 DEV。
波及全部读 `dangerOf` 的路径（投票、破坏、发言）。

性质：**实现层越界**。「能知道自己被沉默」已实现（view.js:71 self 分支），
「能知道别人被沉默」既没实现也没授权。修法两条（AI 不读 / 给真人加可见性）= **产品裁定**。

#### 越界② 异形读 `dying` / `infection`（共 1104 次）——**本批新发现**

`js/ai/decide.js:1173`（感染选目标）：

```js
const pool = ranked.filter(x => !x.x.dying && !x.x.infection).map(x => x.x.id);
```

异形用它排除「濒死者」与「已感染者」以避免浪费感染。
但按声明层：`alien.duty.senses = ["teammateIdentities","teammateBallots"]`
—— **没有任何濒死/感染情报权**。卡片授权 `dyingList` 的只有
rescue / poisoner / tempdoc，授权 `infectMarks` 的只有 bio / rescue / poisoner / tempdoc。

对比：`alienAct` 的**表单**（`steps.js:7`）给的是「存活非异形 + 可指定排除」，
真人看不到谁濒死、谁感染 —— 真人只能盲选，异形 AI 却能排除。
**这是 AI 严格优于真人的一处，且直接提高感染效率。**

#### 越界③ `dying by bio`（446 次）—— 卡片内部的不一致

`decide.js:1187` 医生分支读全场濒死者。
`bio` 有 `infectMarks` 但**没有** `dyingList`（卡片对 bio 的原话只写「可见谁带有感染标记」），
而 `rescue` / `tempdoc` 有。可 bio 与 rescue 共用医生表单（`kind='doctor'`），
引擎侧给了同一份濒死名单。

⇒ 这条**不是 AI 单方面的错，是声明层与引擎的授权口径不一致**：
引擎让所有医生族看濒死，声明层只授权了其中三个。修哪边都要拍板。

#### 归因修正：变形中的死囚

首版把「死囚变形为 alien 后复生」报成「alien 在偷看濒死名单」—— **假归因**。
变形改写 `p.role`（`steps.js:1943`）但不改额度归属（6.8.3），
所以情报权要按 `originRole` 判。修正后这类归到
`dying by convict(变形为alien)`，数量不变但含义正确。

### ③ 合法性与代价 —— 完全对等

`toDecision` 零失败，31 个 kind 全部登记。

## 三、B4 空位：`roleDecl.mind`（零消费）

按你指定的方向在声明层留位：

```js
mind: { gate: '[B4 空位]', life: 'pending', desc: '…' }
// DEFAULTS.mind = { foresight: [], deceive: [], backstab: [] }
```

三层各三个起步取值，共 9 项：

| 层 | 取值 |
|---|---|
| **foresight 预判** | `trendRead` 读趋势下注 / `tempoCall` 押节奏 / `positionBet` 赌站位 |
| **deceive 欺骗** | `falseClaim` 编造宣称 / `feintAction` 行动撒谎 / `omission` 选择性沉默 |
| **backstab 背刺** | `allySacrifice` 牺牲盟友换胜算 / `creditSteal` 抢功 / `trustCashOut` 兑现后翻脸 |

**为什么落在声明层而不是先写 decide.js**：这三个方向要按角色差异化，
而 `roleDecl` 是唯一真源（交接文档 §〇.1）。先写进 decide 就是另一张会漂移的手写表。

**为什么词表要先定**：没有词表的空位 = 任何字符串都能塞的垃圾桶。
等 B4 实装时才发现写歪，那时已有大量数据要清洗。

**空位守卫**（`mindAudit()`，已接进 `audit()`）：

```
pending 状态下任何非空取值都报违例
⇒ 「B4 空位尚未裁定实装，不许声明取值」
```

**严禁在 pending 状态下写入「假装已实装」的值 —— 那是把空位变成假货，比空着更坏。**
审计当场会红。`idleLedger().pendingFields` 现报 `["mind"]`，位空着是可见的。

导出 `MIND_AXES` / `mindOf` / `mindAudit` 是为了让 B4 实装时**只能**从这里取词。

## 六、这一批里我自己踩的坑（都留档在探针注释里）

1. **`form.targets` 有三种形态**：候选数组 / 池描述对象 `{list:'aliveOthers',max:1}` / 单个 id。
   我一律当数组 → 对池描述抛错 → **1443 条决策被误记成「无表单可对照」，白丢七成覆盖面**。
   修正：判形态后分别处理；池描述按 `ui.js:526-531` 的 `targetList` 逐行求候选集
   （自己重写一套 = 拿「我以为的合法目标」判「真人的合法目标」）。
2. **`num.options` 的含义按步不同**：步骤 2 船员的是**待查证身份池**（"crew"/"bio"…），
   而 AI 在那一步返回的 `value` 是 4a 维修预留档（0.25~0.50）。拿身份池比维修档值
   ⇒ **20 次假违例**。修正：只有 `num.options` 全是数字才当数值域查。
3. **假违例必须自己抓**：上面两条若不改，「零违例」会变成一个假的成绩。
   现在 form 抛错计数与样本都显式打印（`formError`），不让它退化成看不出原因的数字。
4. **变形归因**：`p.role` 是伪装目标、`originRole` 才是真身份 —— 情报权按后者判。
