# 新返航录 · 返航录V1

> **11 人类 vs 4 异形**的实时太空船对抗网页游戏（试玩版）。
> 零依赖前端 · 无构建步骤 · 双击 `index.html` 即玩 · 单机 AI 托管对局

- **版本**：返航录V1（`package.json` 语义化镜像 `1.0.0`）
- **仓库**：[GitHub](https://github.com/hxj-2888/space-kill-web) · [Gitee](https://gitee.com/hxj-2888/space-kill-web)
- **许可**：代码 MIT；音效 CC0；场景素材 CC-BY 4.0（详见[素材与许可](#素材与许可)）

## 快速开始

| 方式 | 做法 |
|---|---|
| 直接运行 | 双击 `index.html`（推荐 Chrome / Edge；手机请横屏） |
| 本地服务 | `npm start` → <http://127.0.0.1:5173> |
| 回归门禁 | `npm test`（需要 `playwright-core`，见[开发与测试](#开发与测试)） |

开始页选择「人类」或「异形」即可进入一局；每局 15 席（11 人类 + 4 异形），其余席位由 AI 托管。

## 玩法概要

- **人类**：完成 4 个维修任务（1 高难 + 3 普通），把全船维修进度推到 40 分；或清剿全部异形。
- **异形**：出刀（含对队友）、开枪、钻管道、拉闸、停摆机器人，并可用**每夜一次的破坏技**选一处非会议室舱室下手，削减人类数量。
  异形之间**互不知道身份**；AI 不读取任何队友信息，目标、会议指控和投票都不按阵营过滤，
  因此异形也可能攻击或投掉同类。人类只有目击异形专属行为（出刀 / 钻管道 / 破坏设备 / 停摆机器人）
  才会把对方列为嫌疑人。
- **物资申请单**：每人 4 个任务（1 高难 +2 分 / 3 普通 +1 分）。积分到 3 / 5 只生成「待领取申请单」；
  必须回中央会议室**圆桌**按 `E` 站桩 3 秒领取一张申请单；再到军械库 / 医疗间的**专用补给点**
  按 `E` 消耗 1 张申请单换子弹或医疗包。未领取时补给点会明确拒绝。
- **会议**：发现尸体按 `R` 报告，或点击尸体搜尸后报告；自由发言阶段 AI 会盘口供、质疑与作证，随后投票驱逐并**公布身份**。
- **设施**：配电室电闸（全船熄灯）、监控室 9 路画面（显示真实角色，不是小点）、医疗机器人（每夜最多救 2 人，耗尽后显示电量耗尽）、
  保安机器人（14 格 / 180° 半圆内拘留 60 秒，每夜最多 3 次）、中央会议室圆桌申请单、军械 / 医疗专用补给点，
  以及 22 扇**自动门**（无人闭合、靠近滑开，关门时阻挡移动与视线）。
  两台机器人会在医疗间 / 军械库内**按 4 点路线巡逻**，拘留、施救、交互都按巡逻中的实时位置判定；
  保安 / 医疗机器人都有装甲，可被出刀或开枪摧毁，保安机器人会反制拘留攻击者。
- **硬掩体**：房间内的家具 / 培养罐 / 货箱是真实阻挡，不能穿过；掩体布局保证每个房间有连通绕行通道，
  不存在夹缝走不过去或掩体制造的尽端死路（门禁 `coverAudit()` 零夹缝 / 零死路）。
- **破坏与抢修**：每个异形每夜一次破坏技，按 `H` 选择除中央会议室外的任意舱室，抵达后损毁该舱室设备；
  故障有 60 秒窗口，人类或异形站在设备旁按 `E` **连续维修 10 秒**即可排除（移动会打断）。
  60 秒内未修完且天还没亮，维修进度 **-3**；天亮时未修完的故障不追罚。幽灵不能破坏，但可以参与任务与故障维修（玩家幽灵耗时 1.6×，每只幽灵最多修 **2 分**剩余任务；AI 幽灵目前只飘不修）。
- **站桩维修**：任务维修与故障维修都必须站在设备旁；移动会立即打断并重置计时，不再是“边跑边修”。
- **地图**：9 间舱室（中转间已缩为小型）· 25 个维修点 · 4 个管道口 · 22 扇自动门 · 44 件硬掩体；
  配电室 148 格 / 引擎 216 格，中央会议室管道位于右上角；管道只有异形可用，人类无法打开。
- **濒死与拖尸**：被击倒后进入濒死，可被医疗机器人（每夜 2 次）或医疗包救起；尸体可拖拽藏匿，搜尸可得到死因与移动痕迹。

## AI 与规则模型

本作没有接入外部大模型，所有 AI 都是 `js/game.js` 内的本地规则模型：

- **AI 认知链**：每个 AI 维护自己的 `mind`（事件记忆 / 嫌疑分 / 证据理由 / 警觉度）。
  只记录自己**看见、听见或搜查到**的事实：刀击、枪声、尖叫、管道、拉闸、故障、机器人停摆、
  自动门、灯光变化、拖尸、保安拘留、尸体伤口/是否被移动/是否已检查，以及时间线里见过的人。
  事实进入证据链后按权重累加嫌疑分，再驱动报告、追凶、开枪、指控与投票；AI 不读取任何 `alien` 身份答案。
- **AI 人类**：按任务点维修（与玩家同耗时，无额外倍率）、开局延迟 2–8 秒、任务后休息 6–11 秒、
  回中央会议室圆桌领取物资申请单、到军械 / 医疗专用补给点换子弹 / 医疗包、用医疗包救起视线内的濒死者、
  对目击凶手或高证据目标开枪（人类与异形都可能成为目标；黑暗里只有近身 4.2 格视野）；
  听到尖叫/枪声/刀声且警觉度足够高时，会先去现场查看。
  发现濒死者会先搜尸取得伤口/时间/拖拽痕迹，再决定是否报告；每夜最多触发 1 次 AI 报告，
  没有证据时会议投票弃权而不是随机投人。
- **AI 异形**：追踪最近目标、贴脸出刀、远距离钻管道（20 秒冷却）、指定拉闸手断电、
  顺手停摆机器人、每夜一次破坏舱室；离活人 5 格内优先处理人。
  异形会记住当场目击自己的活人并优先处理；也会在确认没有活人目击时自报尸体，
  用会议时间换取人类维修时间。AI 不读取队友信息，目标/指控/投票都不按阵营过滤；
  异形互相指控或投票不会被视为串通，同类也可能被攻击。
- **会议语料**：开场、口供、质疑、作证、回应、指控、辩护、跟票、弃权均由真实证据和口供生成；
  直接目击会说出“亲眼看见”，时间线冲突会说“对不上”，尸体报告会带上伤口/是否移动/是否已检查。
  台词按席位、夜数、会议轮次与性格轮换，避免全场复读同一句。
- **机器人**：医疗 / 保安机器人各 4 点巡逻；医疗机器人 3 秒施救、每夜 2 次；
  保安机器人 14 格 / 180° 半圆内拘留 60 秒、每夜最多 3 次。机器人可被刀/枪摧毁，保安会反制攻击者。
- **已知边界**：没有跨夜记忆、没有异形全局协同（共享目标 / 串供）、没有长文本语义理解；
  AI 异形仍按“全图最近目标”定位（位置层面全知，但没有身份信息），不会主动寻路到管道口，
  也不会主动维修故障（玩家异形可以）；玩家自由发言只做关键词意图匹配。
  这些是后续接入模型或扩展规则时的优先项。

## 操作

| 按键 | 作用 |
|---|---|
| 鼠标左键 | 移动 / 点选交互 |
| `E` | 交互（任务维修、故障抢修、监控台、地道、圆桌申请单、专用补给点；多项时打开轮盘） |
| `Q` | 出刀（异形；人类没有刀，会提示改用 B） |
| `B` | 开枪（有子弹的人类 / 异形；射程=视野） |
| `F` | 施救（任何角色，需医疗包） |
| `H` | 异形破坏技：靠近机器人时轮盘选择停摆或选舱（每夜一次） |
| `V` | 监控台开关 |
| `R` | 报告尸体 |
| `X` | 搜尸 |
| `G` | 拖拽 / 放下尸体 |
| `T` | 视野切换（手电筒 / 全亮） |
| `C` | 相机切换（跟随 / 全图） |
| `M` | 音效开关 |
| `P` / `ESC` | 暂停 / 关闭弹层 |
| `F2` | DEV 调试面板（仅调试用） |

## 项目结构

```text
index.html                 入口页面（唯一的 script 加载清单）
js/
  config/version.js        版本与元信息（返航录V1 单一真源）
  data/map.js              舰船地图静态数据（房间/走廊/家具/任务点/管道/墙体）
  ui/templates.js          游戏界面 CSS / HTML 模板
  engine/
    clock.js               相位时钟 / 个人技能槽 / 动作请求队列
    invariants.js          对局不变量断言（只读检查）
    geo.js                 几何 / 可行走网格 / A* 寻路 / 视线
  game.js                  对局编排：状态、AI、会议、渲染、输入
  main.js                  开始页绑定与版本号填充
assets/                    场景、角色、底图等素材（许可见各子目录 LICENSE）
audio/                     音效与来源记录（CREDITS.md）
tools/
  serve.cjs                零依赖静态服务器（npm start）
  test-v3.cjs              浏览器断言门禁（Playwright）
  blender-ship.py          2.5D 底图烘焙脚本（需 Blender；读取 js/data/map.js）
```

分层约定：**数据（js/data）→ 引擎（js/engine）→ 编排（js/game.js）→ 入口（js/main.js）**。
所有脚本都是有顺序的经典脚本（IIFE + `window.SK*` 命名空间），不使用 ES Module 与构建步骤。

## 开发与测试

- 无构建：改完源码刷新浏览器即可；新增模块必须同步更新 `index.html` 的加载顺序（依赖自上而下）。
- 门禁：`node tools/test-v3.cjs` 会用 Playwright 跑完整浏览器断言（331 条，含不变量、寻路、会议、音效、机器人巡逻、AI 夜间能力、视野射击、暂停、自动门、硬掩体审计、物资申请单、E/H 交互轮盘、站桩维修、任务乱序维修、幽灵乱序任务/故障维修/2 分额度、AI 认知/证据链/搜尸/异形报告/弃权投票、AI 不读取队友信息/投票可投队友、Q/B 射击分离、AI 与玩家同耗时、保安 14 格 180° 弧形 / 60 秒 / 3 次、机器人受击与摧毁、医疗机器人 2 次电量、F/H 分离、7 类 CC0 音效、统一移速等）。
  默认查找本地 `node_modules` 中的 `playwright-core`，找不到时用环境变量指定：

  ```bash
  PLAYWRIGHT_CORE=/path/to/playwright-core node tools/test-v3.cjs
  SHOT_DIR=./tools/screenshots node tools/test-v3.cjs
  ```

- 测试截图默认写入 `tools/screenshots/`（已忽略，不会入库）。
- 调试入口：`index.html?test`（跳过开局会议直接进夜）、`index.html?dev`、`index.html&strict`。
